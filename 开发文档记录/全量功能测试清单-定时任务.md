# 31 — 定时任务人工测试清单

> 对应功能文档：`页面开发记录/30-定时任务与证书续签.md`
> 测试环境：后端 `8001`、前端 `5173`，使用管理员账号；所有真实域名、AK/SK、Webhook 必须脱敏并在测试环境验证。

## 一、定时任务页面

| 编号 | 操作 | 预期 |
|---|---|---|
| T01 | 重启后端并登录，进入「系统设置 → 定时任务」 | 页面正常加载，无 401/403/500 |
| T02 | 查看任务列表 | 出现 9 个任务：主机健康、应用健康快照、告警引擎、SQL 定时工单、证书到期告警、云账单、预算告警、证书自动续签、域名到期同步 |
| T03 | 查看周期列 | 分别显示 30 秒、5 分钟、1 小时、6 小时、12 小时、24 小时等正确周期 |
| T04 | 服务刚启动时刷新 | 尚未首轮执行的任务显示「等待首轮」，不误报失败 |
| T05 | 等待 30 秒任务跑一轮 | 告警引擎或 SQL 定时工单显示「正常」，累计执行次数增加 |
| T06 | 点击刷新 | 状态更新；正在刷新时图标转动；不会重复提交或报错 |
| T07 | 等待任务异常（可在测试环境暂时制造无效配置） | 页面显示「最近失败」、失败次数和最近错误；runner 不退出 |
| T08 | 关闭/重启后端再打开页面 | 任务统计从新进程重新开始，符合页面说明；不显示旧进程的假数据 |
| T09 | 用无系统管理权限账号访问 | 页面按现有权限体系拒绝访问，不泄露任务状态 |

## 二、证书自动续签

| 编号 | 操作 | 预期 |
|---|---|---|
| C01 | 查看证书列表中 `auto_renew=yes` 的测试证书 | 只有配置了支持的阿里云 DNS 账户才具备自动续签条件 |
| C02 | 准备一条 `status=expiring` 且 `not_after` 在 `renew_before_days` 内的测试证书 | 任务页面显示证书自动续签任务；不需要手工点击签发 |
| C03 | 等待/手动调用一次自动续签 cycle（仅测试环境） | 证书变为 `renewing`，写入 `last_renew_attempt_at`，管理员收到一次「证书自动续期已触发」通知 |
| C04 | 在续签仍运行或失败后再次观察 24 小时内的轮询 | 同一证书不再次触发，不重复发送触发通知；日志出现冷却期跳过记录 |
| C05 | 查看证书详情/后端数据库 | `last_renew_attempt_at` 为最近一次触发时间；不是每轮被刷新 |
| C06 | 将测试证书的 `last_renew_attempt_at` 调整为 24 小时以前 | 下一次轮询允许重新触发；触发时间更新 |
| C07 | 续签成功（使用真实测试域名和有效脱敏凭证） | `status=issued`，`not_after` 更新，`last_error` 清空，后续轮询不重复续签 |
| C08 | 续签失败（测试环境使用无效凭证） | 状态/错误可见；24 小时内冷却，不产生通知轰炸；超过冷却后允许重试 |
| C09 | 同时手工点击续签和等待自动轮询 | `ISSUING_CERT_IDS` 防止同一证书并发执行，只有一个任务进入签发流程 |
| C10 | 重启后端后查看同一失败证书 | 持久化冷却仍生效，不因进程重启立即重新触发 |

## 四、启停和周期配置

| 编号 | 操作 | 预期 |
|---|---|---|
| M01 | 关闭「预算告警」并保存 | 保存成功；该任务状态变为「已停用」；不会继续执行新轮次 |
| M02 | 重新开启「预算告警」并保存 | 保存成功；任务恢复运行，后端不出现两个同 key runner |
| M03 | 将 30 秒任务周期改为 60 秒并保存 | 后端接受；页面显示 60 秒，下一轮按新周期等待 |
| M04 | 输入低于最小值或高于最大值的周期 | 前端限制或后端返回明确 400；原配置不被破坏 |
| M05 | 修改多个任务后只刷新页面、不点击保存 | 草稿提示保留；后台刷新不会覆盖未保存输入 |
| M06 | 点击保存配置 | 所有变更一次提交；刷新后仍显示新配置 |
| M07 | 重启后端再进入页面 | enabled 和 interval_seconds 从 `system_configs` 恢复；运行次数重新从当前进程开始统计 |
| M08 | 停用证书自动续签 | 自动续签任务显示已停用；不再自动触发；手工签发/续签仍可用 |
| M09 | 重新启用证书自动续签 | 恢复扫描，并继续遵守 24 小时失败冷却 |
| M10 | 连续点击保存/刷新 | 请求不导致重复 runner；最终状态与最后一次合法配置一致 |

## 五、其他任务冒烟

| 编号 | 操作 | 预期 |
|---|---|---|
| S01 | 配置一条 30 秒后的数据库定时工单 | 到期后自动执行，结果和通知与手工执行一致 |
| S02 | 配置云账号并等待账单同步周期或手动触发同步 | 同步记录可见，失败不会让 runner 停止 |

| S05 | 配置域名到期同步 | 域名列表的到期时间来自同步后的本地缓存 |
| S06 | 部署多个后端 worker 前先确认架构 | 只启用一个后台 runner 实例，避免账单、证书、告警等任务重复执行 |
