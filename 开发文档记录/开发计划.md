### P9 — 后台任务 / 异步任务推送站内信 ⬜ 待开发

> 目标：把散落在各模块的异步任务（主机采集、证书签发/续期、Agent 安装、发布等）
> 统一到一套「任务状态可追踪 + 终态推送站内信」的机制上。

**现状盘点（已具备的底子）**
- ✅ `create_notification(db, data=NotificationCreate(...))` 写库 + `publish_notification()` 进程内 `asyncio.Queue` 广播 → SSE 端点推前端 → `receivePush` 实时插入铃铛
- ✅ 已有 23 处调用点（assets / certificates / vms / monitoring），"任务完成→发站内信"模式已在多模块落地
- ✅ 异步任务基于 `asyncio.create_task` + `threading`，随 Web 进程生命周期（无 Celery / 独立 worker）

**已识别的隐患**
1. **进程内广播 = 单进程假设**：`_sse_subscribers` 是模块级 dict，多进程（gunicorn -w N / 多实例）下任务在 A 进程完成、SSE 连在 B 进程会丢推送（库有记录不丢，"实时"丢失）
2. **线程内 DB session 归属**：`threading.Thread` 后台任务必须每次 `SessionLocal()` 新开、用完即关，禁止复用请求期 `db`（否则连接泄漏 / session 复用报错）
3. **进程重启 = 执行中任务静默消失**：任务跑一半重启，既不完成也不发失败通知，用户永远等不到结果——缺任务状态表托底

**开发任务（按性价比排序）**
- [ ] **P9.1 薄封装 `notify_task_done()`**（小改动，先做）
  - 统一 success/error 语义、统一 category 命名，收敛 23 处裸调用
  - 签名：`notify_task_done(db, *, user_id, task_type, ok, title, detail="", link=None, resource_id=None)`
- [ ] **P9.2 `async_tasks` 任务状态表**（中期，动 DB + 多任务点）
  - 字段：`id / task_type / status(pending|running|success|failed) / progress / error / created_by / resource_id / created_at / updated_at`
  - 任务开始落 `running`，结束更新终态并发通知；进程重启后可扫描"僵尸 running"任务
  - 站内信只作"终态通知"，详情点进任务记录看（长错误不塞进通知 content）
  - 为后续"任务中心"页面预留数据源
- [ ] **P9.3 多进程广播方案（上生产前决策）**
  - 单进程：现状够用
  - 多实例：Redis pub/sub 替换进程内 Queue，或轮询兜底

**产品规范（本次确立）**
- 站内信只承载**终态结果**（成功/失败），**不承载进度**
- 有过程的任务（主机采集 / Agent 安装）：进度走 SSE / 轮询实时刷 UI，**仅在结束时发一条站内信**，避免铃铛被进度刷屏
- 现行主机采集（轮询刷列表 + 结束发通知）即为标准分工
