## 二、问题清单与修复（按严重度）

### P0 三条已索票的写操作，审计全记「低」危（安全，后端）

`AUDIT_RISK_ROUTE_RULES`（`app/main.py:344-380`）只覆盖了集群子路径，
漏了三类**已经挂着 `require_risk_ack`（前端会弹确认）** 的写操作——

| 路由 | 后端实参 | 缺失后果 |
|---|---|---|
| `PUT /clusters/{id}` 编辑集群 | edit | 改集群名/连接信息，审计记 low |
| `PATCH .../resources/{ns}/{kind}/{name}/edit` 表单化编辑 | edit | 等价 `kubectl edit`，审计记 low |
| `DELETE .../resources/{ns}/{kind}/{name}` 通用删除 | delete | **等价 `kubectl delete`，最大缺口**，审计记 low |

另有 `ACTION_RISK_LEVELS`（`app/core/rbac.py`）四个动作未登记 → 回落 low，
审计页风险列不可信：`patch_labels`（节点/ns 标签）、`scale`、`create_namespace`。

**修复**：
- `AUDIT_RISK_ROUTE_RULES` 补 4 条（PUT 集群 edit、PATCH 资源 edit、
  DELETE 通用资源 delete、POST `pods/.../exec/session` exec_session —
  logs/session 只读日志低敏，不补）；
- `ACTION_RISK_LEVELS` 补登记 `patch_labels`/`scale`/`create_namespace`/`exec_session`
  均为 **medium**（改动共享状态但不破坏集群承载能力）；
- **不改变任何索票行为**——这些路由的 `require_risk_ack` 本就在，只修审计等级。

**回归校准**：`test_risk_ticket_contract.py` 里「未注册动作也能拿票」的用例原本拿
`clusters:patch_labels` 举例（现已注册为 medium），改用 `clusters:logs` 并补注释；
新增 `test_short_key_second_round_registered_cluster_actions` 钉死本轮四项等级。

### P2-1 搜索「搜得到、跳不准」（前端）

点搜索结果只切 Tab，丢弃 name/namespace（跳到资源浏览看到的是默认 Service 列表）；
后端 search 的 kinds 参数前端也没用。

**修复**：`detail.tsx` onNavigate 带上 ns/kind/name，通过 URL 参数跳到目标 Tab 并
定位（Pods 预填关键字+ns 并高亮；工作负载同理；其他 kind 进资源浏览预选 kind/ns）。
`GlobalSearchBox` 加 kinds 多选（后端只实际搜索 8 种 kind，常量与后端 `_search_*`
分支对齐）。

**新增 `detail/useTabParams.ts`**——URL 即筛选单一数据源：

```ts
export const focusValue = (kind, namespace, name) => `${kind}|${namespace}|${name}`
export function useUrlFilter(key, fallback = '')   // 读 URL、写 URL（replace 模式）
export function useUrlFocus(): string              // 读 focus 参数
export const focusRowClass = (focus, kind, ns, name) => 'cluster-row-focused'
```

踩坑：`useSearchParams` 的函数式 updater 收到的是**闭包里那份 searchParams 的拷贝**，
同一事件里连续改两个筛选项会互相覆盖——setter 改为在调用时读 `window.location.search`。

### P2-2 实时动态信息量不足（前端，零后端改动）

MODIFIED 事件行只显示资源名（SSE 帧里的 `object_summary` 有状态却被丢掉）；
5 次退避重连失败后无手动入口，只能关抽屉重开。

**修复**：`ClusterLiveFeed.tsx` 渲染 `object_summary`——
Pod 显示「状态 · 就绪 · 重启 N 次」，负载显示「状态 · 就绪」；
标题区加「重新连接」按钮（`reconnectKey` 进 effect deps 实现手动重连），
5 次失败后空态给出「连接已断开（退避重连 5 次仍未恢复）」+ 重连入口。

### P2-3 状态与缓存（前端）

ns/kind/关键字全是组件 state，刷新、分享链接、前进后退全丢；同一个 namespaces
接口两套 queryKey（`['cluster-namespaces']` vs `['cluster-namespaces-list']`）双缓存
不同步；删除用 `refetch()` 不用 invalidate；资源列表 `limit` 写死 200，大集群 200 条后
直接看不到（后端 `paginated`/`continue_token` envelope 现成却没接）。

**修复**：三个 Tab 的筛选全部迁到 URL（`useUrlFilter`）；namespaces 统一为单一
queryKey `['cluster-namespaces', cid]`；删除改 `invalidateQueries({ queryKey:
['cluster-…', cid] })` 让所有 Tab 列表同步刷新；资源列表接
`resourcesPage(cid, kind, ns, 100, continueToken)` + `useInfiniteQuery`，
每页 100 条，底部「加载更多」按钮，取完自动消失。

**GUI 回归时发现的连带问题（顺手修）**：资源浏览切 kind 会把 ns 重置成「全部」
（`onChange={(v) => { setKind(v); setNamespace('_all') }}`）——命名空间是 kind 无关的，
重置既丢筛选又丢 URL 参数。已改为只改 kind、保留 ns。验证：
`?tab=resources&kind=Secret&ns=airspace` 切成 ConfigMap 后 URL 变成
`?tab=resources&kind=ConfigMap&ns=airspace`，列表仍只出 airspace 的 ConfigMap。

YAML/诊断/关联资源四处全是裸 `<pre>`，无复制按钮。

**修复**：
- `OverviewTab` 加 `issueLocate()`/`issueTab()`：Pod → Pods Tab（带 ns+name+focus），
  负载 → 工作负载 Tab，节点 Node → 节点 Tab，其他 kind → 资源浏览；
  Top 问题行与核心组件异常行均可点击，鼠标手型 + Tooltip + 「定位 →」后缀；
- 新增 `components/k8s/YamlPre.tsx`（复制按钮 + 1.5s「已复制」+ `maxHeight` 限高滚动），
  替换工作负载 YAML 抽屉、资源 YAML 只读态、Pod 诊断、关联资源四处 `<pre>`；
  **刻意不引语法高亮库**（AGENTS.md：新增依赖先问），保持零依赖。

## 四、过程中发现并规避的两个坑

1. **dev 后端进程不加载最新代码**：GUI 回归审计 Tab 时发现筛选无效、IP 列全空、
   `/openapi.json` 里 audit-logs 仍是 `limit ≤ 200` 旧签名——而代码是新的。
   排查：`--reload` 的父进程活着，但实际服务进程早于当次编辑启动且未热加载。
   处理：重启 dev server 后全部恢复（IP 显示 127.0.0.1、筛选生效、`{items,total}`）。
   **教训：GUI 回归前先用 `/openapi.json` 的请求参数核对进程加载的是最新代码**，
   否则会把"后端明明改了却不生效"误判成前端 bug。
2. **`useSearchParams` 函数式 updater 的闭包拷贝**：同一处理器连续写两个筛选项时
   第二个会覆盖第一个（详见 P2-1），setter 改为调用时读 `window.location.search`。
