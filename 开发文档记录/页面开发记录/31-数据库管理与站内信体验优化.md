# 31 — 数据库管理与站内信体验优化

> 日期：2026-09-21
> 范围：`pages/assets/databases/index.tsx`（重写）、`pages/notifications/index.tsx`（重写）、
> `components/layout/NotificationBell.tsx`、`store/notifications.ts`、`api/index.ts`、
> 后端 `app/api/notifications.py`（list 增加分类/关键词筛选）
> 起因：用户要求"数据库管理的 UI/UX 体验更好一点，站内信也做好一点"

---

## 一、原则

只改信息架构、交互与反馈，**不动配色/背景/装饰**（遵守 AGENTS.md 第 1 条）；
顺带修掉两处违反项目规范的真实问题（静态 `Modal.confirm`、渲染期 setState 反模式）。

## 二、数据库管理页

### 1. 顶部概览卡片（新增，与资产页视觉对齐）

4 张卡片：数据源 / 连接异常 / 待审批 / 待执行。**点击卡片即联动筛选**：
点「待审批」跳到工单 Tab 并按 pending 过滤，卡片描边高亮当前筛选。
数据源异常卡一键跳到数据源 Tab。

### 2. 工单 Tab 角标 + 定时执行提示

- Tab 标签带待审批数量角标，审批人不用点进去就知道有没有活；
- 页面底部 Alert 提示"当前有 N 张已批准工单等待定时执行"。

### 3. 工单筛选：关键词搜索（客户端即时过滤）

工单全量拉一份（limit 200），状态 + 关键词（标题/实例/提交人/库名）在前端过滤，
筛选零请求零延迟；空态区分"没有符合条件的工单"和"暂无工单"。

### 4. 批量批准

表格加行选择（仅 pending 可勾选），选中后出现操作条：
**批量批准（带 SQL 摘要确认）**。批准前弹窗展示每张工单 `#id + SQL 前 60 字符`，
避免误点；`Promise.all` 逐张提交，完成后统一刷新。

### 5. 高危操作确认重做（修规范问题）

- 原来驳回用**静态** `Modal.confirm`（违反规范 7"用 App.useApp() 实例"）→ 改为 `modal.confirm`；
- 原来执行走 `useRiskConfirm().confirm()`，而该 hook 已被改为直通放行（无任何确认）→
  改为 `modal.confirm` 并展示**目标实例 + SQL 摘要 + 自动备份说明**，执行前看得见将跑什么；
- 批准/驳回按钮加 `loading`（按 mutation variables 精确匹配行）。

### 6. 提交工单：Modal → Drawer（修规范问题）

原 680px Modal 里塞 SQL 编辑器 + 库表浏览器，严重违反规范 3
（"新增/编辑用 Drawer + Form，不用 Modal，除非字段极少"）。改为 920px Drawer：
- SQL 编辑区 14 行，库表浏览器 8 / SQL 16 双栏；
- **Ctrl / Cmd + Enter 快捷提交**（标题栏有 ⌘⏎ 提示 Tag）；
- 审核规则说明从正文挪到 `extra`，不再挤占编辑区。

### 7. 工单详情抽屉

- SQL 块加**复制按钮**（clipboard + 失败降级提示）；
- 审核结果从 div 堆叠改为 `List`（规则 Tag + 说明，超过 4 条也不炸）；
- SQL 块限高 240px 可滚动。

### 8. 自助查询 Tab

- **Ctrl / Cmd + Enter 快捷执行**（输入框下有提示）；
- 结果 NULL 值弱化为次要色，和真实值区分；
- 工具条重排：实例/库选择在左，执行按钮在右，说明文字归位。

### 9. 审核规则 Tab：修渲染期 setState 反模式

原 `useEffectRulesInit` 在**渲染期**用 `setTimeout(setDraft)` 塞数据
（setState-in-render 的 hack，保存后还会被旧草稿覆盖）。改为标准
`useEffect(() => { if (data?.rules?.length) setDraft(data.rules) }, [data])`，
query 引用不变则不重入，保存失效后自动同步服务端值。

## 三、站内信（通知中心 + 铃铛）

### 1. 后端：list 增加分类/关键词筛选（`app/api/notifications.py`）

`GET /notifications` 新增 `category`（精确匹配）与 `q`（标题/内容 LIKE）参数。
- LIKE 通配符转义 + `escape="\\"`（用户输入 `%` 不会匹配全部——SQLAlchemy 的 `.like()`
  不发射 ESCAPE 子句，第一版漏了导致转义反而不匹配，契约测试抓住）；
- 新参数用**普通默认值**而非 `Query()`：本仓库测试直接调用路由函数，`Query()` 默认值会漏进来
  （第一次提交就因此炸了 6 个存量测试）；
- 新增 4 个契约测试：分类筛选、标题/内容搜索、通配符转义、分类+关键词组合。
  **352 passed**。

### 2. 通知中心页（重写）

| 改进 | 说明 |
|---|---|
| 分类筛选 | 下拉含 证书/主机/虚拟机/Agent/数据库/监控/资产/应用/系统，与后端在用分类对齐；分类 Tag 按语义着色 |
| 关键词搜索 | 标题/内容后端搜索，300ms 防抖，不清空不重查 |
| 时间分组 | 今天 / 昨天 / 更早 分组头（sticky），长列表不用逐条看日期 |
| 未读强标识 | 左侧 3px 蓝竖条 + 浅蓝底 + 标题加粗，未办事项一眼定位 |
| 跳转提示 | 有 link 的通知在时间旁显示"查看详情 →"，点击整条进业务页 |
| 空态 | 区分"暂无通知"与"没有符合条件的通知"，后者给"清除筛选条件"按钮 |
| 文案 | 副标题说明什么会通知你（告警/工单审批/证书/资产变更） |

### 3. 铃铛下拉

- 每条显示**分类 Tag**（原来只有类型图标，分不清是证书还是数据库）；
- 未读条目 hover 出**单条"已读"按钮**（原来只能整条点击跳转才标记已读）；
- 标题/内容超宽省略，20 条上限不变。

### 4. store 修复：本地即时通知标记已读打错接口

`local-` 前缀是会话级即时通知（后端未落库），`markRead`/`markAllRead` 原来无条件调
后端 → 404 → catch 里再 `refreshUnread`。现在 `local-` 跳过请求；
`markAllRead` 在没有后端记录时也跳过。
