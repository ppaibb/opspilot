# P0 安全加固：权限票据、Grafana、Kubeconfig 与部署秘密

## 一、范围与结论

本次封堵六项 P0：用户删除越权、风险票据越权签发、Grafana Auth Proxy
请求头冒充、Kubeconfig 丢失或进入镜像、根 Compose 弱口令与运行时建表、
开发监控默认凭证，以及离线安装脚本泄露密码和宽松文件权限。

修复原则是 fail-closed：缺权限、缺秘密、缺可信代理来源时直接拒绝，不再以
默认口令、空白名单或自动建表兜底。

## 二、加固后架构

```mermaid
    E --> C[原子消费票据]

    D --> V[backend-storage 持久卷]

    I[install.sh umask 077] --> S[.env 0600]
    S --> X[显式数据库/Grafana 密码]
    X --> M[Alembic 显式迁移]
```

## 三、问题与修复

| P0 | 根因 | 修复 |
|---|---|---|
| 任意用户删除用户 | 删除路由只有风险票据依赖；票据签发不校验权限 | 签票、消费、删除路由三处都校验实时 RBAC；撤权后的旧票据不可消费 |
| Grafana 请求头冒充 | `auth.proxy` 未限制来源且 3000 对外监听 | 强制 `GF_AUTH_PROXY_WHITELIST`；同机默认仅回环监听，并通过专用 Docker 网络访问 |
| Kubeconfig 丢失/进镜像 | 文件位于代码临时目录，忽略规则不完整 | 默认写入 `/app/storage/kubeconfigs`；旧文件安全迁移；新旧目录均加入构建忽略和秘密扫描 |
| 根 Compose 弱密码/自动建表 | 公开默认数据库密码，业务进程执行 `create_all` | 密码改为必填；新增 `init-db` 执行 `alembic upgrade head`；业务进程关闭自动建表 |
| 开发 Grafana 默认凭证 | 管理员密码可使用公开默认值 | 密码必须显式提供；镜像升级到 `11.6.14-security-04` |
| 安装脚本泄密 | `.env` 受调用者 umask 影响，摘要打印明文密码 | 进程级 `umask 077`，所有替换后显式 `chmod 600`，终端只打印账号和配置位置 |

## 四、兼容与迁移

### Kubeconfig

启动时只迁移旧目录中系统生成的 `c-*.yaml` 普通文件。符号链接和其他文件名
会被忽略；目标存在时绝不覆盖；写入新文件并设置私有权限成功后才删除旧文件。

### Grafana

离线同机部署创建 `opspilot-monitoring-bridge` 专用网络，后端使用
`http://grafana:3000`。升级已有环境时，只在数据库现值精确等于旧安装器生成的
`MONITORING_HOST:3000` 时迁移；域名、TLS、非标准端口等人工配置保持不变。

分体部署需要把 `GRAFANA_BIND` 设为受控私网地址，并将
`GRAFANA_AUTH_PROXY_WHITELIST` 精确限制为 OpsPilot 后端来源，禁止使用
`0.0.0.0/0`。
