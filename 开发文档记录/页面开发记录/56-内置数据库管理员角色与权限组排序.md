## 一、数据库管理员预设（rbac.py ROLE_TEMPLATE_PRESETS）

插在 运维 与 开发 之间。权限：`PERMISSION_DEFAULTS` 基线 + `module.dashboard` +
`module.ai.ops` + **`module.assets.databases`**（页面）+ `module.settings.im`
+ **db 四件套**（manage / submit / execute / approve）——SQL 工单全生命周期 +
数据源维护。注意 `action.db.manage` 自带副作用（持有者自助查询豁免授权校验），
description 已写明。

- 插入 presets 字典即自动成为**系统组**（`is_system_role_template` 按字典键判定）：
  可编辑权限内容、不可删除不可改名，与其它预设一致；
- 建用户：用户管理的角色下拉自动出现该角色（同一 `list_role_templates` 数据源）。

## 二、排序修复（list_role_templates）

原排序 `(系统组在前, 标题 Unicode 码点)` → `只读 / 域名管理员 / 开发 / 管理员 / 运维`
——码点序与任何语义都无关，看起来就是乱序。

改为：

```python
preset_order = {role: idx for idx, role in enumerate(ROLE_TEMPLATE_PRESETS)}
result.sort(key=lambda item: (
    (0, preset_order.get(role, len(preset_order)), "") if item["is_system"]
    else (1, 0, item["title"])
))
```

系统预设按**定义顺序**（管理员 → 运维 → 数据库管理员 → 开发 → 域名管理员 → 只读），
自定义组排在其后按名称。权限管理列表、用户管理角色下拉同源生效。

## 五、删除「角色标识」列（同日追问：「角色标识这一列有用么？看起来不好看」）

核实结论：**纯冗余**。`title` 与 `role` 恒等——预设角色两者同值；自定义角色创建/更新
接口（settings.py `create_role_template`/`update_role_template`）强制 `title = role_name`。
列内代码样式内容与「权限组」列逐字重复。

删除后表格收敛为四列：**权限组 / 描述 / 权限数 / 操作**，描述列获得整段宽度。
验证：lint 0 error、检查-全量 4/4 全绿、235 已部署（浏览器断言表头恰为四列、0 失败请求）。
