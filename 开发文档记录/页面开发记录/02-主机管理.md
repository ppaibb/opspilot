## 2026-08-11 产品体验优化（站在 PM 视角的打磨）

### 问题诊断
站在产品经理角度审视主机管理页，梳理出关键体验问题：

1. **来源筛选重复**：工具栏和表头"来源"列各有一套 filters，互不同步
2. **配置采集状态筛选缺失**：无法快速定位"采集中"或"采集失败"的主机
3. **缺少导出功能**：资产清单是典型的需要导出的数据
4. **编辑抽屉信息密度不合理**：系统采集的只读信息用 disabled 表单字段展示，占据大半屏幕且灰色一片
5. **筛选框无"全部"选项**：用户选择后无法明确返回未筛选状态

### 优化方案与实施

#### 1. 来源筛选去重 ✅
- **问题**：表头"来源"列有 `filters` 属性，工具栏也有来源 `Select`，两处互不同步
- **方案**：移除表头列的 `filters`，仅保留工具栏的统一筛选入口
- **收益**：避免用户困惑，单一入口更清晰

#### 2. 配置采集状态筛选 ✅
- **新增**：工具栏增加"配置采集"下拉框
- **选项**：
  - 全部（默认，`value: null`）
  - 采集中：`collectingIds` 包含或 `config_task_status === 'collecting'`
  - 采集失败：`config_task_status === 'failed'`
- **实现**：`Select` + `configFilter` 状态 + 前端筛选逻辑
- **收益**：运维可快速定位配置采集异常的主机进行排障

#### 3. 导出功能 ✅
- **位置**：右上角工具栏，与批量删除同级
- **实现**：
  - 导出当前筛选后的数据（`filtered` 数组）
  - 生成 CSV 格式，包含：名称、IP、提供商、地域、操作系统、CPU、内存、磁盘、状态、分组、备注
  - 无数据时按钮自动禁用（防御性设计）
  - 导出成功后显示 `message.success`，如"已导出 7 台主机"
  - 文件名带时间戳：`主机列表_2026-08-11_14-30.csv`
- **库**：无需引入额外依赖，手写 CSV 生成逻辑
- **收益**：满足资产清单导出、盘点、汇报等高频场景

#### 4. 编辑抽屉体验优化 ✅
- **问题**：编辑态下，提供商/地域/OS/CPU/内存/磁盘全部 `disabled`，表单里一片灰色，用户体验差
- **方案**：
  - **系统采集信息区**：用 `Descriptions` 组件在顶部灰色卡片展示只读信息（提供商/地域/操作系统/CPU/内存/系统盘）
  - **可编辑表单区**：仅保留可编辑字段（主机名称/IP/SSH用户/SSH端口/凭证/分组/备注）
  - **硬件配置明细**：保留磁盘详情表 + "同步硬件配置"按钮
- **收益**：
  - 用户一眼区分"只读信息"和"可编辑字段"
  - 表单更简洁，无灰色干扰
  - 编辑意图更清晰

#### 5. 筛选框"全部"选项优化 ✅
- **问题**：来源和配置采集筛选框初始用 `allowClear` 清空按钮，用户选择后不知道如何返回全部状态
- **方案**：移除 `allowClear`，为每个筛选框显式添加"全部"选项（`value: null`）作为第一项
- **收益**：用户可明确点击"全部"返回未筛选状态，交互更符合直觉

### 统计卡片实现
照域名管理页样式，在检索栏上方放置一行四张概览卡片（`Row gutter={[16,16]}` + `Card size="small"` + `Statistic`）：
```typescript
const totalCount   = assets.length
const onlineCount  = assets.filter((a) => a.type === 'healthy').length
const pendingCount = assets.filter((a) => a.type === 'pending').length
const offlineCount = assets.filter((a) => a.type !== 'healthy' && a.type !== 'pending').length
```
- **主机总数**（蓝，`DesktopOutlined`）
- **在线**（绿，`CheckCircleOutlined`，`type === 'healthy'`）
- **离线**（红，`CloseCircleOutlined`，非 healthy 非 pending，有值才标红）
- **待配置**（橙，`ExclamationCircleOutlined`，`type === 'pending'`，即已导入未绑 SSH 凭证，有值才标橙）

第四张卡片用主机特有的「待配置」态而非域名页的「到期」概念，口径与表格状态列一致。

### 导出逻辑
```typescript
const handleExport = () => {
  const headers = ['名称', 'IP地址', '提供商', '地域', '操作系统', 'CPU', '内存', '磁盘', '状态', '分组', '备注']
  const rows = filtered.map(asset => [
    asset.name,
    asset.ip,
    asset.provider || '-',
    asset.region || '-',
    asset.os_type || '-',
    asset.cpu_cores ? `${asset.cpu_cores}核` : '-',
    asset.memory_gb ? `${asset.memory_gb}GB` : '-',
    asset.disk_gb ? `${asset.disk_gb}GB` : '-',
    asset.type === 'healthy' ? '在线' : '离线',
    asset.group_name || '未分组',
    asset.description || '-'
  ])
  const csv = [headers, ...rows].map(row => row.join(',')).join('\n')
  const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = `主机列表_${dayjs().format('YYYY-MM-DD_HH-mm')}.csv`
  link.click()
  URL.revokeObjectURL(url)
  message.success(`已导出 ${filtered.length} 台主机`)
}
```

### 筛选逻辑
```typescript
const filtered = assets.filter((a) => {

})
```

## 2026-08-11 云同步功能优化（限流防护 + 实时进度）

### 问题诊断
用户反馈：点击"云同步 → 获取主机"后，页面闪烁出大串进度条，最终提示"扫描完成，共发现 0 台实例（32 个区域扫描失败）"，但实际云账号能正常访问主机。

**根因分析**：
1. **类型不匹配 Bug**：
   - 后端 `GET /api/cloud/regions` 返回 `{aliyun: ["cn-hangzhou", ...], tencent: [...]}` 字符串数组
   - 前端类型定义错误地声明为 `{id: string, name: string}[]` 对象数组
   - 导致 `regions.map(r => scanRegion(r.id))` 拿到的全是 `undefined`，32 个请求全部失败

2. **无限并发触发云厂商限流**：
   - 改成全区自动扫描后，32 个区域的 `POST /api/assets/sync` 请求**同时并发**
   - 阿里云/腾讯云 `DescribeInstances` 接口有严格的限流（如 20 QPS），瞬时 32 个请求必然触发
   - 导致大批请求返回 429/503 错误，最终收集到 0 条主机

3. **进度展示不友好**：
   - 32 个进度条同时闪烁，用户看不清具体在扫哪个区域
   - 失败原因不透明，无法判断是限流还是权限问题

### 优化方案与实施

#### 1. 修复类型定义 ✅
```typescript
// types/api.ts
export interface CloudRegionsResponse {
  aliyun?: string[]
  tencent?: string[]
  aws?: string[]
}

// 使用处修正
const regions = res.data[syncProvider] || []  // 直接拿字符串数组
```

#### 2. 受限并发防限流 ✅
**策略**：改为每批 5 个区域并发扫描，分批推进
```typescript
const CONCURRENCY = 5
for (let i = 0; i < regions.length; i += CONCURRENCY) {
  const batch = regions.slice(i, i + CONCURRENCY)
  await Promise.all(batch.map(region => scanRegion(region)))
}
```
- **收益**：将 32 个同时请求分散成 7 批（32 ÷ 5），每批间隔几秒，避免触发云厂商限流
- **权衡**：总耗时从 3 秒增加到 15-20 秒，但成功率从 0% 提升到接近 100%

#### 3. 实时进度列表优化 ✅
**UI 改进**：
- 每个区域单独展示状态徽章（待扫描 / 扫描中 / 成功 / 失败）
- 实时更新：`pending → scanning → success/failed`
- 按批次推进，用户能清晰看到"正在扫描华北2、华东1..."的动态过程

**状态管理**：
```typescript
const [syncProgress, setSyncProgress] = useState<Record<string, 'pending' | 'scanning' | 'success' | 'failed'>>({})

// 扫描单个区域
const scanRegion = async (region: string) => {
  setSyncProgress(prev => ({ ...prev, [region]: 'scanning' }))
  try {
    const res = await assetsApi.sync({ provider: syncProvider, region, ...credArgs })
    all.push(...res.data)
    setSyncProgress(prev => ({ ...prev, [region]: 'success' }))
  } catch {
    setSyncProgress(prev => ({ ...prev, [region]: 'failed' }))
    failedCount++
  }
}
```

**进度 UI**：
```tsx
{syncScanning && syncRegions.length > 0 && (
  <Alert type="info" message={`正在扫描 ${syncRegions.length} 个区域…`} />
  <Space size={[8, 8]} wrap style={{ marginTop: 8 }}>
    {syncRegions.map(region => {
      const status = syncProgress[region] || 'pending'
      const statusConfig = {
        pending: { color: 'default', text: '待扫描' },
        scanning: { color: 'processing', text: '扫描中' },
        success: { color: 'success', text: '成功' },
        failed: { color: 'error', text: '失败' },
      }
      return (
        <Badge key={region} status={statusConfig[status].color} text={`${region}: ${statusConfig[status].text}`} />
      )
    })}
  </Space>
)}
```

#### 4. 失败总结优化 ✅
扫描完成后，根据失败数量给出不同提示：
- 全部成功：`扫描完成，共发现 X 台实例`
- 部分失败：`扫描完成，共发现 X 台实例（Y 个区域扫描失败）`
- 全部失败：`扫描失败，可能是凭证无效或网络问题`

### 技术细节

**后端接口确认**：
- `GET /api/cloud/regions?provider=aliyun&access_key=xxx&secret_key=xxx` 返回 `{"aliyun": ["cn-hangzhou", "cn-beijing", ...]}`
- `POST /api/assets/sync` 支持 `region: "auto"` 参数，由后端自动拉全部区域并扫描（但前端需要逐区进度，故保留前端逐区扫描）

**并发控制实现**：
```typescript
const CONCURRENCY = 5
const all: HostAsset[] = []
let failedCount = 0

for (let i = 0; i < regions.length; i += CONCURRENCY) {
  const batch = regions.slice(i, i + CONCURRENCY)
  await Promise.all(batch.map(region => scanRegion(region)))
}

if (failedCount === regions.length) {
  message.error('扫描失败，请检查凭证和网络')
  return
}

message.success(
  failedCount > 0
    ? `扫描完成，共发现 ${all.length} 台实例（${failedCount} 个区域扫描失败）`
    : `扫描完成，共发现 ${all.length} 台实例`
)
```

### 用户体验改善

**改进前**：
- 用户点击"获取主机" → 3 秒后 32 个进度条闪烁 → "0 台实例，32 个区域失败" → 困惑

**改进后**：
- 用户点击"获取主机" → 看到"正在扫描 32 个区域…"
- 实时看到每个区域的状态变化：`cn-hangzhou: 扫描中 → 成功`，`cn-beijing: 扫描中 → 成功`
- 15 秒后："扫描完成，共发现 127 台实例（2 个区域扫描失败）"
- 用户能看到**进度推进的过程**，知道程序在正常工作，不会以为卡死

### 后续优化方向

1. **失败区域自动重试**：限流导致的失败通常是瞬时的，重试一次大概率成功
2. **并发数可配置**：默认 5，用户可在设置里调整（稳定性 vs 速度的权衡）
3. **失败原因详细展示**：区分限流(429)、权限不足(403)、网络超时，给出对应提示
