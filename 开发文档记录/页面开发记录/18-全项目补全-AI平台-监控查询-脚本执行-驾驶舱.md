## 一、关键 Bug 修复（存量问题）

**AI 工作台三处响应解包错误**（页面从未上线所以从未暴露）：
- `GET /ai/sessions` 返回 `{sessions: []}`，前端按裸数组消费 → 列表渲染必崩
- `GET /ai/skills` 返回 `{skills: []}`，同上
- `GET /ai/configs` 返回 `{items: [], active_id}`，激活配置取 `c.active` 但后端字段是 `is_active`

修复方式：在 `api/index.ts` 的 `aiApi` 层统一解包归一化，页面代码零改动。

## 二、AI 平台四页

### 模型配置 `/ai/llm-config`
- 配置 CRUD：Provider（Gemini / OpenAI 兼容 / Claude）+ 模型 ID + Base URL（兼容模式必填校验）
- 采样参数：温度滑杆 / 最大 Tokens / 超时；系统提示词
- **激活机制**：同一时刻单配置生效，列表高亮「激活中」
- **连通性测试**：抽屉内即时探测（不落库不打扰激活态），显示延迟/明细
- 安全：API Key 服务端加密存储，列表只回 `has_api_key` 标记；编辑留空 = 沿用原密钥

### 技能管理 `/ai/skills`
- 按分类分组的技能卡片墙：风险等级标签、示例问法、开关
- **草稿式批量保存**：本地 toggle → 显式「保存」落库，避免误触；支持全开/全关/按分类切换
- 搜索过滤 + `action.ai.skills.manage` 权限控制

### AI 全景看板 `/ai/dashboard`
- 四指标卡：会话 / 消息 / 今日消息 / 参与用户（真实表统计）
- 近 7 天消息趋势柱状图（ECharts）+ 消息构成（提问 vs 回复）
- 运行时模型卡（当前激活配置 + 跳转管理）
- AI 审计日志 Top10 + 最近会话列表（点击跳工作台）

### 编排中心 `/ai/orchestration`（第一版：策略治理）
- 策略配置：审批门禁 / 预算护栏 / 超时 / 步数上限 / 审批人数 / 工单要求
- 高风险动作清单（只读，服务端维护）
- **预检模拟器**：输入操作元信息 → 返回 放行/需审批/阻断 + 原因 + 命中风险动作
- 画布编排（React Flow）留待后续版本，本版先立策略护栏

## 三、监控查询两页（真实现）

### 指标查询 `/monitoring/metrics`（替换 stub）
- **双模式**：区间查询（多序列折线图，时间戳对齐断线重连） / 即时查询（表格快照）
- **指标浏览器**：label 名 → 取值两级浏览（`__name__` 即全部指标名），点击取值自动填入查询框
- 6 个常用 PromQL 模板一键填充
- 提交后才发请求（`submitted` 模式），避免输入过程打爆 VM

### 日志查询 `/monitoring/logs`（替换 mock）
- LogsQL 查询 + 时间范围 + 行数上限，结果倒序（最新在上）
- **时间直方图**：随查询联动的命中量分布（ECharts）
- **上下文抽屉**：点击行查同 stream 前后 N 行，当前行高亮
- **Live Tail**：fetch-SSE 消费 `/logs/tail`（EventSource 无法带 Bearer 头故用 fetch 流），
  环形缓冲 500 行、可停止/清空、离开页面自动断流；服务端 5 分钟超时保护

## 四、脚本执行 `/tools/script`（新建）

四 Tab 结构，全部对接后端 Ansible 引擎：
1. **执行**：目标主机多选（`ansible_ready` 未就绪主机置灰 + 原因提示）+ 三模式
   （ad-hoc 模块速选 / Playbook YAML 编辑 / 从模板）+ `useRiskConfirm` 高危确认 + 结果面板
   （stdout/stderr/耗时/命令预览）
2. **批量模板**：CRUD + 授权权限组 + 绑定主机/全部主机 + 一键执行
3. **执行历史**：全员记录 + 详情抽屉
4. **Ansible 配置**：启用开关 / 可执行文件 / forks / 超时 / 主机密钥校验 + 控制端可用性展示
