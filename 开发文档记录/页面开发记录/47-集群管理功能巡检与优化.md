## 二、问题清单与修复（按严重度）

### P1-1 集群运维整族动作零确认（安全）

`ACTION_RISK_LEVELS` 里集群只注册了 `delete`。cordon / drain / set-image /
rollout-undo / restart / uncordon / patch_taints / resize_pvc / trigger_cronjob /
suspend_cronjob 十个动作**未注册 → 回落 low → 前端不弹确认框**，而后端
`consume_risk_ticket` 照常索票（前端静默换票）。结果：一次误点就把生产节点标记
为不可调度、或驱逐节点上全部 Pod，界面无任何确认。

**修复**：`backend/app/core/rbac.py` 批量注册——
cordon/drain/set-image/rollout-undo = **high**（弹高危确认），
uncordon/restart/pause/suspend_cronjob/trigger_cronjob/patch_taints/resize_pvc = **medium**。
前端 `useRiskConfirm` 对 high 弹 `高危操作确认` 框，框内文案点名单个目标
（「将把节点 k8s-01 标记为不可调度：新 Pod 不再调度上来，已有 Pod 保持运行；
如目的是下线节点，请改用排空」），不再出现「该操作风险等级为高危（clusters:cordon）」这种
要用户自己猜的黑话。

### P1-2 YAML 工作台 apply 全链路不可用

`server_side_apply` 未传 `field_manager`，K8s ≥1.28 的 apiserver 对 apply-patch
强制要求该字段，直接 422 `fieldManager: Required value`——试运行能过、应用必失败。

**修复**：`backend/app/api/clusters/_shared.py` 固定 `_SSA_FIELD_MANAGER = "opspilot"`
（稳定标识，同源重复 apply 不因管理者不同而冲突）。
**GUI 验证**：填 Pod YAML → 试运行（`✅ Pod/airspace/smoke-gui-pod`）→ 应用到集群 →
Pod 在 k8s-04 上 Running、审计落 `/apply`（medium）→ 冒烟 Pod 已删除清理。

### P2-1 核心组件表：外置措辞 + 占位 Pod 名 + etcd 自相矛盾

三宗罪：外置组件状态显示「内嵌/外置」；Pod 列把目标名 `apiserver` 当成 Pod 名展示；
RKE 拓扑下 **etcd 同时出现两行**——分类占位行「etcd 外置」+ componentstatuses
追加行「etcd-0 正常」。

**修复**：
- 后端 `cluster_mgmt.py`：componentstatuses 命中占位行时**覆盖**而非追加
  （新增 `_match_component_target`，`etcd-0 → etcd`），不存在 Pod 的组件只留一行权威健康度；
- 前端 `OverviewTab.tsx`：状态改中文（正常/异常/控制面外置/未发现）并挂 Tooltip 解释外置语义，
  占位行 Pod 列渲染「—」。GUI 验证：`apiserver | — | 控制面外置 | -`、`etcd | etcd-0 | 正常 | OK`。

### P2-2 操作审计：时间偏差 8 小时 + 动作对象两列重复 + 高危全标 low

`audit_logs.time` 是 naive UTC，原样 `isoformat()` 给前端，UTC+8 下整体早 8 小时；
`action`（「创建 /api/clusters/xxx/dry-run」）与 `resource`（同一路径）两列重复；
`AUDIT_RISK_ROUTE_RULES` 只有「删除集群」一条规则，其余集群操作一律记 low，
审计页的「高危高亮」对集群操作完全失效。另外 `AUDIT_METHOD_ACTION_MAP` 缺 **PATCH**，
集群写操作全是 PATCH，等于不落审计或误标「读取」。

**修复**：
- `cluster_mgmt.py` 审计接口：`to_local_str(log.time)` 转本地；action 拆出方法标签
  （创建/更新/删除/读取），resource 去 `/api/clusters/{cid}` 前缀，新增 `path` 字段供悬浮查看；
- `main.py`：`AUDIT_METHOD_ACTION_MAP` 补 `PATCH: 更新`；`AUDIT_RISK_ROUTE_RULES`
  补 20 条集群子路径规则（cordon/drain/apply/set-image/rollout-undo/pod 删除/ns 删除/resize_pvc…），
  等级与 rbac 注册表同源；
- 前端 `AuditTab.tsx`：风险列中文化（高危/中危/低）、对象列 code 样式 + 完整路径 Tooltip、
  结果列识别 `failed`。
**验证**：cordon 记录 = 高危、uncordon = 中危、时间 `2026-10-08 16:28:03`（本地）。

### P2-3 命名空间用量裸 JSON + 系统命名空间可连点两次确认才被拒

用量卡片直接 `<pre>{JSON.stringify(usage)}</pre>`；kube-system/default 等核心命名空间
前端可点删除，过两道确认后才被后端 403 拒绝。

**修复**：`NamespacesTab.tsx` 用量改结构化（Descriptions 概览：Pod 数/CPU requests/
内存 requests/ResourceQuota + Top Pods 表格，kube-system 实测 `22 | 1.49 核 | 0.674 Gi | 未设置`）；
`shared.tsx` 新增 `PROTECTED_NAMESPACES`（与后端 `namespaces.py` 常量对齐），
核心命名空间删除按钮前置禁用 + Tooltip「集群核心命名空间，禁止删除」。GUI 验证四行均 disabled。

### P2-4 Pods 操作列三个"文档形"图标不分

终端/日志/诊断依次是 code/file-text/file-search，后两个形状近似、悬停才分清。

**修复**：`PodsTab.tsx` 诊断图标改 `MedicineBoxOutlined`（医疗箱），
三个图标形态彻底分开（code / file-text / medicine-box），Tooltip 补说明文案。

### P3-1 详情页头部 "vv1.32.6"

`v{cluster.version}` 而 version 已带 `v` 前缀。修复为 `{cluster.version}`（GUI 验证）。

### P3-2 YAML 工作台误点遮罩静默丢内容

maskClosable 默认开，遮罩一碰整段 YAML 没了。
**修复**：`maskClosable={false}` + 关闭拦截（有未保存内容时弹「关闭 YAML 工作台？
已填写的内容不会保留」，`dirtyRef` 跟踪，apply 成功后同步清零避免误弹）。
GUI 验证：点遮罩不关、Esc 后内容完好、点 × 才出确认框。

### P3-3 集群列表 ⋯ 按钮无 Tooltip

入口旁两个按钮都有 Tooltip，只有 ⋯ 没有。修复为「更多操作（编辑 / 解除纳管）」。

## 四、遗留观察（未改，记录在案）

1. **IAB 自动化环境**里 antd 弹窗有"关闭动画卡死"现象（`.ant-modal-wrap` 残留
   `modalDisplay:none`），是浏览器自动化渲染产物，非产品缺陷；真实浏览器不复现。
2. 工作负载操作列 icon 按钮多达 9 个（CronJob 行 11 个），目前靠 Tooltip 区分。
   已逐项核对语义无重复，暂不加「更多」折叠——高频操作（scale/restart/回滚/删镜像）
   一键可达更重要；若后续反馈拥挤再收敛。
3. `refresh 同步`只更新快照字段（版本/节点数/水位），节点实时用量依赖 metrics-server，
   缺装时用量条优雅降级为仅容量，文案已说明。
