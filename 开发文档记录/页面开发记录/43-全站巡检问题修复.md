# 43 - 全站巡检问题修复（2026-10-03）

> 对应 2026-10-03 第四轮全站 GUI 巡检发现的 3 个 P1 + 6 个 P2 问题。
> 全部修复附契约测试，统一验证入口 `检查-全量.bat` 全绿。

---

## P1-1 告警重复通知无收敛（最重要）

**现象**：`OpsPilotHostCpuHigh_192_168_3_99` 持续 firing 3 个月，企业微信通道重复通知发到第 2302 次
（默认 `reminder_interval_minutes=30` 匀速 forever）；两张证书告警未绑渠道，
`未绑定任何通知渠道` info 日志刷了 317 行。

**修复**（`app/api/monitoring/services/alert_dispatcher.py`）：

1. **按告警年龄升级提醒间隔** `_effective_reminder_interval_minutes()`：
   - 0-2h：用配置间隔（默认 30 分钟，行为不变）
   - 2-8h：至少 2 小时一次
   - 8-48h：至少 8 小时一次
   - 48h+：至少 24 小时一次
2. **超龄停发**：新增设置键 `reminder_max_age_hours`（默认 168h=7 天，0=不限制），
   超过后停止重复通知；告警保留在中心，恢复通知不受影响。规则级可覆盖（`active_rule.reminder_max_age_hours`）。
3. **日志降噪**：`未绑定任何通知渠道`/`已达最大通知次数`/`超龄停发` 改为按
   (告警,实例) 1 小时窗口节流（`_log_throttled`）；`未满间隔跳过` 从 info 降为 debug
   （每 30s 评估周期都会走到，原来每天每告警刷 2880 行）。

**兼容性**：2 小时内的行为与原版完全一致（既有 7 个告警契约测试全绿不改动）；
新设置键缺省时走默认值，存量 `system_configs` 无需迁移。

## P1-2 K8s 核心组件健康全部 not_found

**现象**：k3s 型集群（本环境 local-k8s）控制面不以静态 Pod 运行，
apiserver/etcd/scheduler/controller-manager/kube-proxy 全显示 not_found，误导排障。

**修复**（`app/api/clusters/cluster_mgmt.py` + `OverviewTab.tsx`）：

- 匹配逻辑抽成纯函数 `_classify_core_components(pods)`（带 kubeadm/k3s 双命名别名表）；
- 控制面组件无 Pod 时不再标 `not_found`，改标 `external`（k3s 内嵌/云托管外置均属正常拓扑）；
  coredns 无 Pod 仍标 `not_found`（它必须以 Pod 跑）；
- 前端状态列 `external` 渲染为蓝色「内嵌/外置」。

## P1-3 审计日志时间偏差 16 小时

**根因**（`app/api/settings.py` get_audits）：`AuditLog.time` 以 `datetime.utcnow()` 落库（naive UTC），
序列化却写 `log.time.astimezone(timezone.utc)`——Python 把 naive 值当**本地时间**再转 UTC，
UTC+8 机器上等于凭空减 8 小时（实际操作 23:14 显示 07:14）。

**修复**：`log.time.replace(tzinfo=timezone.utc).astimezone()`——显式按 UTC 解释再转本地时区展示。
全库仅此一处该错误写法（`grep astimezone(timezone.utc)` 复核，另一处 routes.py 是 aware 值的正确用法）。

## P2-4 日志直方图 X 轴全部 08:00:00

**根因**：当前 VLogs（192.168.3.99:9428）的 `/select/logsql/hits` 返回 **RFC3339 字符串**
（`"2026-10-03T15:20:00Z"`），`_normalize_hits_ts_seconds` 只会 `float()` → 失败返回 0 →
所有桶落在 epoch 0（UTC+8 显示 08:00:00）。

**修复**（`app/api/monitoring/routes.py`）：归一函数增加 ISO 分支——
`fromisoformat` 解析（无时区按 UTC，与全站外部存储时间约定一致）后转 Unix 秒；数字分支不变。
补 timezone 顶层导入（原代码在函数内局部导入，顶层引用会 NameError）。

## P2-5 模型配置更新时间显示原始 ISO 微秒串

**根因**：LLM 配置 `created_at/updated_at` 以 `datetime.utcnow().isoformat()` 落库（naive UTC），
原样吐给前端（`2026-09-22T15:00:35.563909`）。

**修复**（`app/api/ai_agent.py`）：`_normalize_stored_llm_entry` 序列化时经
`_fmt_utc_iso_local()` 转本地时间 `YYYY-MM-DD HH:mm`。存量数据（UTC ISO）与新增数据统一生效。

## P2-6 仪表盘环比裸数字

仪表盘「本月云消费」环比从 `环比 -418.29` 改为 `环比 -418.29（-98.8%）`，
口径与费用总览页一致（mom_delta / prev_total）。

## P2-7 通知铃铛下拉横向溢出

`NotificationBell.tsx`：标题行 flex 子项加 `minWidth: 0`（Space 可收缩 + ellipsis 生效）、
Tag/时间 `flexShrink: 0`；List `overflowX: hidden`。长标题不再撑出横向滚动条。

## P2-8 宽表格操作列

复核结论：主机/虚拟机/凭证/域名/证书五张表的操作列**已有** `fixed: 'right'` + `scroll={{x}}`，
巡检截图中的表现实为固定列正常工作 + 表格可横向滚动，非缺陷，不改。

## P2-9 工作负载列表混入历史 ReplicaSet

`WorkloadsTab.tsx`：类型筛选默认值从 `_all` 改为 `Deployment`，
历史 ReplicaSet 不再把真正的控制器刷出首屏；需要时手动切「全部类型」。
