## 一、分角色用户与登录引导修复（本次最大发现）

**发现 P1 级产品缺陷：任何非管理员账号都无法登录使用系统。**

- 根因：前端登录引导（AuthGuard bootstrap）对所有用户必需调用
  `GET /api/settings/rbac/metadata` 与 `GET /api/settings/users/{id}/access`，
  而这两个接口都挂着 `module.settings.users` 权限 → 普通用户 403 →
  「初始化失败，用户信息或权限数据加载失败」死页。
  这解释了为什么系统运行 3 个月只有 admin 一个真实用户。
- 修复（`app/api/settings.py`）：
  1. `rbac/metadata` 放宽为仅需登录（数据为权限目录与模板定义，非敏感；
     授权管理页面另有页面级守卫）；
  2. `users/{id}/access` 改为"查自己只需登录，查他人要求用户管理权限"
     （在函数体内二分校验，不能用 require_permissions 依赖表达）。
- 新增 e2e `test_normal_user_bootstrap_chain` 钉死该链路。

**测试用户**（开发库，保留）：

| 用户 | 密码 | 角色 | 说明 |
|---|---|---|---|
| ops01 | Ops@12345 | 运维 | 主机/监控/脚本等 57 项权限 |
| dba01 | Dba@12345 | DBA（新建自定义角色） | 数据库管理 + db 三权 + 告警/日志查看 |

**分角色实测结论（GUI + API）**：
- viewer01：登录进系统 ✓；侧栏无资产管理/费用管理 ✓；直访用户管理页 403 拦截页 ✓
- 工单三权流（API 驱动）：ops01 提交 UPDATE 工单 → **自审批被 403 拒绝**
  （`不能审批自己提交的工单`，分权拦截早已存在）→ dba01 跨角色审批 →
  dba01 执行 → smoke 表数据真实变更 → ops01 收到「审批通过/执行成功」两条站内通知 ✓
- 待办（记录未修）：仪表盘「活跃告警」卡未按权限隐藏（viewer 显示 0）；
  「系统设置」一级菜单对只读角色未隐藏（子项已部分过滤，个人 IM/定时任务/权限管理仍可见）

**附带修复：空邮箱唯一约束 bug。** 创建用户不填邮箱时 email="" 直接入库，
撞 `ix_users_email` 唯一索引 → 第二个无邮箱用户必 500。改为存 NULL（PG 唯一索引对 NULL 去重），
存量空串已 UPDATE 为 NULL。e2e 回归覆盖。

## 二、五件事落地情况

1. **Alembic 全量迁移修复 ✅（生产化最大风险解除）**
   - 根因：`0001_initial_schema` 不是静态快照而是按当前模型 `create_all`，
     后续 21 个迁移的 create_table/add_column/create_index 在空库全量 upgrade 时全部重复
     （首个断点 `9fbe4a2c470f` DuplicateColumn: assets.hostname）；
     另有 head 修订号 33 字符超过 alembic 默认版本表 VARCHAR(32)。
   - 修法：`app/alembic_guards.py` 幂等守卫（列/表/索引 存在即跳过）+
     批量改写 21 个迁移文件调用守卫版 + env.py 预建 VARCHAR(64) 版本表。
   - 结果：空库从 base `upgrade head` **首次跑通**，51 张表逐列与当前模型比对一致。
     验证脚本 `scripts/verify_alembic_full_upgrade.py`（重建临时库→upgrade→diff→清理）可进 CI。
   - 存量库兼容：守卫是幂等的，stamp 后跑尾部迁移语义不变。

2. **真实用户分发 ✅（以本节用户体系代替）**：三角色账号 + DBA 角色模板就绪，
   IM 渠道既有（create_notification fanout 已在工单流验证发出站内信）。

3. **告警工单化闭环 ✅（第一锁定范围）**

     活动列表带 `acknowledged_note`（响应模型同步补字段——曾因漏补被 FastAPI 过滤）。
   - 前端：行内「确认」升级为「认领」弹窗（处理备注 textarea）；
     列表显示「已认领 · 认领人」；详情时间线含备注；详情内可「释放认领」。
   - e2e：认领→备注→列表可见→释放→再释放 404 全链路（写后还原不留脏数据）。

4. **时间处理收口 ✅**
