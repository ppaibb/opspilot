# 42 - 资产管理前后端契约修复

> 更新时间：2026-09-25

**背景**：对资产管理模块（主机 / 虚机 / 凭证 / 域名 / 证书 / CMDB）做一次前后端联通专项审查：
前端 5 个页面的表单组包、`api/index.ts` 封装、`types/api.ts` 类型，与后端 6 个路由文件
（assets / vms / credentials / domains / certificates / cmdb）的 Pydantic schema 与处理器逐字段比对，
并用源码路由表核对全部路径与方法（192.168.3.99:8001 的 `/openapi.json` 返回 401 且带网关信封，
联机契约拿不到——该端口前面可能挂了别的东西，待确认）。

共确认 5 个真 bug + 5 个次要问题，全部修复。

## 🔴 Bug 1 — 虚机新增：Proxmox 虚机从 UI 创建必然 400

**根因**：后端 `create_vm` 对 PVE 的流程要求 `template_vmid > 0`（模板克隆）或 `boot_iso` 非空
（全新创建），否则 `400 全新创建虚机时请选择 ISO 镜像`；而前端抽屉表单只有
name/provider/node/ip/os/cpu/内存/磁盘/备注 9 个字段，provider 默认值就是 `proxmox`，
**默认路径 100% 失败**。后端配套的 `/vms/nodes`、`/vms/storages`、`/vms/isos`、`/vms/bridges`、
`/vms/templates` 接口前端一个都没消费。

**修复**（`pages/assets/vms/index.tsx` + `api/index.ts` + `types/api.ts`）：

- 新增 PVE 创建资源下拉，仅「新增 + Proxmox + 抽屉打开」时拉取（`enabled` 控制，不白打请求）：
  - 宿主节点：`GET /vms/nodes`（allowClear，清空走后端默认节点）
  - 存储池：`GET /vms/storages?node=`，默认 `local-lvm`
  - 网桥：`GET /vms/bridges?node=`，默认 `vmbr0`
  - 模板：`GET /vms/templates`（可选，选中后走模板克隆）
  - ISO：`GET /vms/isos?node=`，校验规则「模板与 ISO 至少选一个」（`dependencies` 联动模板）
  - 创建后自动开机：Switch → `start_after_create`
- 节点切换联动重拉存储/网桥/ISO（queryKey 带 node）
- 模板克隆时把所选存储池作为 `target_storage` 下发（克隆盘落盘位置可预期）
- 非创建态 / 非 Proxmox 供应商不渲染这组字段，行为不变

**教训**：后端先做的能力（模板克隆 / ISO 创建 / 节点存储下拉）前端没跟上，
表单还在用「手填节点」的旧契约——新增能力上线时要同步检查前端表单是否消费。

## 🟠 Bug 2 — 虚机批量删除：部分失败谎报全部成功

后端返回 `{success_count, failed: [{id, reason}]}`（PVE 配置未完成时 failed 全量），

## 🟠 Bug 3 — 域名状态：下拉选项与后端校验脱节

前端把 STATUS_MAP 的 4 个 key（active/expiring/expired/inactive）直接渲染成状态下拉，
后端 `validate_domain_update` 只接受 **active/offline**——选「即将到期/已到期/停用」保存必 400。
且后端真实的 `offline` 值反而不在前端映射表里。

**修复**（`pages/assets/domains/index.tsx`）：

- STATUS_MAP 补 `offline`（展示用，`inactive` 保留为历史数据兜底）
- 状态下拉只提供 `active` / `offline` 两项，extra 注明「即将到期/已到期按到期时间自动判定」

## 🟠 Bug 4 — 主机编辑：SSH 凭证清不掉（静默回绑旧凭证）

凭证下拉不是 Form.Item（无 name），保存时 `credential_ref: credentialRef || v.credential_ref || ''`——
用户 allowClear 清空后 `credentialRef=''`，但 `v.credential_ref` 是编辑回填的旧值，
兜底又把旧凭证塞回去。只能「换绑」不能「解绑」。

**修复**：payload 以选择框状态为准 `credential_ref: credentialRef || ''`，
去掉对表单预填旧值的回落。（`pages/assets/hosts/index.tsx`）

## 🟠 Bug 5 — 凭证编辑：AccessKey 只填 AK 会把已存 SK 清空

`buildContent` 的注释只防了「两个都留空 = 不改动」，但只填 AK 留空 SK 时照样组装
`{"access_key":"...","secret_key":""}` 并 `replace_content: true`——已存 secret_key 被覆盖成空串，
之后账单同步 / 云区域拉取突然鉴权失败，很难排查。

**修复**（`pages/assets/credentials/index.tsx`）：

- AccessKey 半填（填了一个留空另一个）直接拦截报错「需要成对填写，留空表示不改动」
- 顺带堵上同类洞：编辑时换了凭证类型但没填新密文 → 拦截
  （否则旧密文如明文密码会挂在 SSH Key 类型下）
