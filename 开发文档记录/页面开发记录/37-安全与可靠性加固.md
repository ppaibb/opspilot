## 1. 高危操作确认：直通放行 → 一次性票据

**改造前问题**
- `require_risk_ack` 依赖前端带 `X-Risk-Ack: true` 头，而该头是无条件附加的——任何人用 curl
  手工构造请求带上这个头就能绕过"二次确认"，后端从未真正校验过用户确认了这个动作。
- 安全契约测试曾因"直通放行"改过断言（见 29 号文档），等于把妥协固化进了测试。

**改造后机制**
- 后端新增 `POST /api/auth/risk-challenge`：登录用户为某个动作签发**一次性票据**，
  TTL 120 秒，绑定 用户 + 动作（permission_key/action_id/resource_id）。
- `require_risk_ack` 改为强制校验 `X-Risk-Ticket` 头：票据存在、属于当前用户、匹配动作、
  未过期、未消费，校验通过后**原子消费**（并发重复使用同一张票只成功一次）。
- 前端 `useRiskConfirm` 重写：high 等级先弹确认框（用户点确认才去取票），取到的票据只附加在
  **下一个**请求上，用完即弃；删除了无条件 `X-Risk-Ack: true` 头。
- 新表 `risk_ack_tickets`（含 `short_key` 标记，见遗留事项）。

**涉及文件**
- 后端：`app/api/auth.py`（risk-challenge 签发）、`app/core/security.py`（require_risk_ack 校验与原子消费）、`app/models/risk_ticket.py`、`app/db/models.py`（注册）
- 前端：`src/hooks/usePermission.ts`（useRiskConfirm）、`src/api/client.ts`（票据附加下一个请求）、`src/api/index.ts`
- 迁移：`alembic/versions/20260922_security_hardening_merge.py`

**回归测试**：`test_risk_ticket_contract.py`

## 2. K8s：Watch 会话收敛 + Secret 密文不回显

**改造前问题**
- K8s Watch session 只是一张"集群通行证"，换人复用同一 session 也能看完整事件流；
  kinds/namespace 过滤只在前端做。
- K8s Secret 的 `data`/`stringData`（base64 即明文）会原样出现在 detail/YAML/edit 接口里，
  能读集群的人就能把所有密文拖走。

**改造后机制**
- Watch session 创建时绑定 用户 + 权限 + kinds/namespace 范围，服务端按绑定范围过滤事件，
  越界事件不下发。
- Secret 的 `data`/`stringData` 在 detail / YAML / edit 三条通道一律不返回，接口只回占位标记；
  apply/YAML 保存时服务端保留原密文——用户在前端看到的空占位**不会**以"空白覆盖"真实 Secret。

**涉及文件**：`app/api/k8s_watch.py`、`app/services/k8s_informer.py`、`app/api/clusters.py`、`app/api/cluster_routes/cluster_resources.py`、`app/api/cluster_routes/cluster_base.py`

**回归测试**：`test_k8s_watch_auth_contract.py`、`test_k8s_secret_redact_contract.py`

## 3. 数据库管理：CTE 绕过封堵 + 只读会话 + 工单原子认领 + 数据隔离

**改造前问题**
- 自助查询的"仅只读"校验按顶层语句判断，`WITH x AS (DELETE FROM t RETURNING *) SELECT * FROM x`
  这类 CTE 写法可以从只读通道里执行写操作。
- 执行引擎连接本身没有只读兜底——审核层一旦漏判，数据库层也拦不住。
- SQL 工单 approved→executing 是普通 UPDATE，双开页面同时点"执行"会并发跑两次。
- 工单列表 / 查询日志对所有能进页面的人全量可见，A 实例的提交人能看到 B 实例的工单和 SQL。

**改造后机制**
- CTE 判写：WITH 内含 `INSERT`/`UPDATE`/`DELETE`/`MERGE` 的语句直接判为写，自助查询 422 拒收。
- 执行层只读会话：自助查询连接先设只读——PG `SET default_transaction_read_only = on`，
  MySQL 设 `transaction_read_only`；审核层是第一道门，数据库层是第二道。
- 工单原子认领：approved→executing 改为条件 UPDATE（`WHERE status='approved'`）认领制，
  只有一个请求能认领成功，其余请求得到"已被执行/状态已变化"。
- 数据隔离：工单与查询日志按提交人隔离，本人只能看自己的；持有特权角色的账号（审批/执行/管理员）可见全量。

**涉及文件**：`app/api/database.py`、`app/services/db_ops.py`

**回归测试**：`test_db_ticket_atomic_contract.py`、`test_db_isolation_contract.py`

## 4. JWT 会话撤销 + 通知 SSE 票据化

**改造前问题**
- JWT 签出后直到过期前无法作废：重置密码、禁用账号后，旧 token 依然一路绿灯。
- 通知 SSE 把长期 JWT 直接拼在 EventSource URL 上——URL 会进浏览器历史、代理与访问日志。

**改造后机制**
- `users.token_version` 会话版本号：签发 JWT 时写入当前版本，校验时比对；
  重置密码 / 禁用账号时递增版本，所有已签发旧 token 立即 401。
- 通知 SSE 改为**一次性短票据**（60 秒有效）：先调接口用 JWT 换短票，再用短票连 SSE，
  长期凭证不再出现在 URL。

**涉及文件**：`app/models/user.py`、`app/core/security.py`、`app/api/auth.py`、`app/api/settings.py`（重置密码/禁用递增）、`app/api/notifications.py`、迁移 `20260922_security_hardening_merge.py`（token_version 列）

**回归测试**：`test_token_revocation_contract.py`、`test_notification_sse_ticket_contract.py`

## 5. SSH 主机指纹 TOFU 钉扎

**改造前问题**
- Paramiko 连接策略是 `AutoAddPolicy`——任何主机密钥都无条件接受，中间人（DNS 劫持/ ARP 欺骗/
  换机）拿到的凭据和执行的命令全都不设防；全库多处直连代码各自为政。

**改造后机制**
- 首连自动记录指纹（TOFU，Trust On First Use），落 `asset_host_keys` 表（host+port+key_type 唯一）；
  之后每次连接比对指纹，**变化即拒绝**并明确报错，不再静默续连。
- 全部 `AutoAddPolicy` 移除；SSH 连接收敛到统一入口。

**涉及文件**：`app/services/ssh_client.py`（`pin_and_connect` 统一入口）、`app/models/asset_host_key.py`、
调用方：`app/api/assets.py`、`app/api/certificates.py`、`app/api/terminal_ws.py`、`app/services/wireguard_status.py` 等

**回归测试**：`test_ssh_host_key_contract.py`
**遗留**：「重新确认指纹」管理入口待上线——目前指纹变化只能拒绝连接，机房换机后需要人工处理（见文末）。

## 6. 后台任务租约（防多 worker 重复执行）

**改造前问题**
- scheduler 的周期任务、云账单同步、应用发布都是进程内直跑：部署从单 uvicorn 升级到多 worker /
  多实例时，同一任务每个进程各跑一份——告警重复发、账单重复同步、发布重复执行。

**改造后机制**
- 新表 `task_leases`（lease_key 唯一 + owner + 心跳 + 过期时间）：任务执行前先拿数据库租约，
  拿到才跑，拿不到说明别的实例在跑；持租约方定期续心跳，实例崩溃后租约到期自动释放。
- 三条链路已接入：scheduler 周期任务、云账单同步、应用发布。
- **调度器 fail-open**：租约表不可用（如表还没建）时放行执行并告警日志——宁可极小概率重复，
  不能让任务整体停摆。

**涉及文件**：`app/services/leases.py`、`app/models/task_lease.py`、`app/services/bill_sync.py` 及 scheduler 各 runner、迁移 `20260922_security_hardening_merge.py`

**回归测试**：`test_task_lease_contract.py`

## 7. 前端：路由单一数据源 + 403/404 + lint 清零

**改造前问题**
- 路由表、侧边栏菜单、权限过滤三处各维护一份清单，加页面要改三处，漏一处就出现"菜单有入口、
  路由 404"或反之。
- 登录后 bootstrap（拉权限）失败会静默放行——权限全空却照样进系统，页面按无权限渲染成一堆空壳。
- 告警规则页残留裸 `fetch`；vms 电源操作的风险动作键与其他页面不一致。

**改造后机制**
- 统一到 `src/router/routes.ts` **单一数据源**：38 条路由全部懒加载 + 携带权限键，菜单/面包屑/
  全局搜索/权限过滤全部从它派生，新增页面只改这一处。
- 新增 403 / 404 页面；无权限访问与未知路径有明确兜底，bootstrap 失败不再静默放行（明确报错引导重试）。
- 告警规则页改走统一 api 实例；vms 电源操作票据动作对齐（统一 `poweroff`）；eslint 存量 error 清零。

**涉及文件**：`src/router/routes.ts`、`src/router/index.tsx`、`src/components/layout/menuConfig.tsx`、
`src/pages/403.tsx`、`src/pages/404.tsx`、`src/pages/monitoring/alerts/*`、`src/pages/assets/vms/*`、`src/hooks/usePermission.ts`

**端到端冒烟脚本**：`scripts/smoke_ticket_e2e.py`（用法见文件头）。

原理：对"不存在的资源"调用受保护路由当探针——票据正确则守卫放行、业务层返回
404/422，票据缺失/重放则守卫先拦（401/403），两种结果可区分且零副作用。对
users:disable 这种"404 早于票据校验"的路由，建临时账号走真实闭环后清理。

实测：34 个前端动作键 × 4 步 + 跨动作票据 + 启用无票 + SSE 票据 =
**144 项检查全绿**。冒烟同时抓到"集群列表页编辑缺守卫"（第 7 条）并修复。

跑法：
```bat
REM 1. 起后端（开发库，8019 端口）
cd backend && .venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8019
REM 2. 另开终端跑冒烟
.venv\Scripts\python.exe scripts\smoke_ticket_e2e.py
```

## 遗留事项

1. ~~**vms 电源操作票据动作键**~~ 已统一为 `poweroff`；权威键表见上文，新增高危动作按表执行。
2. **SSH 指纹管理入口待上线**：指纹变化目前直接拒绝连接，尚无页面可查看/重置已钉扎指纹
   （`asset_host_keys`），机房合法换机后需要人工清库才能恢复连接。
3. **短键票据跨模块碰撞风险**：`risk_ack_tickets.short_key` 支持前端短键（如 `assets:delete`）
   换票，短键粒度低于完整权限键，不同模块若复用同一短键会互相放行——新增高危动作建议
   优先使用完整权限键。
4. **调度器 fail-open**：租约表异常时任务照跑（见第 6 节），多实例部署需保证表已建好，
   否则防重复执行形同虚设。
5. **生产环境必须 `alembic upgrade head`**：本轮三张新表 + `users.token_version` 都在迁移
   `20260922_security_hardening_merge` 里；生产（`DB_AUTO_CREATE_TABLES=0`）不会自动建表，
   不跑迁移高危确认、SSH 钉扎、任务租约、会话撤销全部失效。
6. **工单卡死 executing 的恢复已补**（`recover_stale_executing_tickets`，启动时+定时器
   开头调用，超 2 小时标 failed），但"崩溃窗口内 SQL 已部分执行"仍需人工核对目标库。
7. **`credentials` 加密导出**口径变更：后端 batch-export 无口令参数，前端"口令加密
   .opspilot-cred"改为 ZIP + manifest 直出。
