# 顶栏增强 & 站内通知开发记录

**涉及文件**：`components/layout/` 下多个 + `store/notifications.ts`
**状态**：✅ 前端完成（通知数据源待后端接口切换）

---

## 需求来源

1. 用户点了证书续期，几分钟后状态还是 renewing —— 异步任务结果无反馈
2. 用户可能离开页面，需要「站内信」在回来时仍能看到操作结果
3. 顶栏正上方偏空，需要填充有价值的内容

---

## 一、顶栏三件套

顶栏从「仅右侧用户头像」改为「左面包屑 / 右侧搜索 + 铃铛 + 用户」。
为避免 MainLayout 变成巨石文件，全部拆成独立组件。

| 组件 | 文件 | 说明 |
|---|---|---|
| 菜单配置 | `layout/menuConfig.tsx` | 菜单树从 MainLayout 抽出，共享给面包屑/搜索；含扁平化路由 `flatRoutes` 和 `resolveBreadcrumb()` |
| 面包屑 | `layout/Breadcrumbs.tsx` | 跟随路由自动生成层级（仪表盘 / 资产管理 / 证书管理），可点击跳转 |
| 全局搜索 | `layout/GlobalSearch.tsx` | AutoComplete 搜页面名跳转，**Ctrl+K / Cmd+K** 唤起 |
| 通知铃铛 | `layout/NotificationBell.tsx` | Badge 角标 + 下拉通知列表 + 全部已读 |

MainLayout 从内联 ~90 行菜单定义瘦身，只负责组装。

## 二、站内通知系统

### 前端状态：`store/notifications.ts`（Zustand）

```
AppNotification { id, type, category, title, content, link, resourceId, isRead, createdAt }

push(n)       — 新增一条（会话级）
setAll(items) — 用后端列表整体替换（接口 ready 后用）
markRead(id) / markAllRead() / remove(id) / clear()
unreadCount   — 自动计算未读数，铃铛角标直接用
```

### 数据源设计（关键）

当前是**会话级**：`push()` 往内存加通知，刷新页面清空。
设计成**数据源可切换**：后端通知接口 ready 后，改为轮询
`GET /api/notifications` 调用 `setAll()`，UI 完全不用动。

### 已接入的演示

证书续期成功时 `pushNotification()` 推一条 info 通知，铃铛角标即时变红。

## 三、后端接口需求（已交付后端）

文档：`开发文档记录/后端接口需求-站内通知.md`

核心接口：
- `GET /api/notifications`（含 unread_count）
- `GET /api/notifications/unread-count`（轻量轮询角标）
- `POST /api/notifications/{id}/read` + `read-all`
- 可选：SSE 实时推送 `/notifications/stream`

后端在异步任务（证书续期/签发、虚机同步、Agent 安装）结束时写通知记录。
