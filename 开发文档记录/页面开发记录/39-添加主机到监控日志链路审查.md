## 关键修复

### 1. PromQL instance 匹配（P0）

**问题**：`instance=~"{host}.*"` 是前缀匹配，`192.168.1.1` 会把 `192.168.1.10` 的指标也算进来。

**修复**：新增 `prom_instance_regex()`（`app/api/monitoring/services/dashboard.py`）：
- 后缀用 `(:.*)?`（匹配 `host` 或 `host:port`），不再用 `.*`
- 点号用 `[.]` 字符类（本环境 VM 对 `\\.` 转义返回 422）
- 其余元字符 `re.escape`，防主机名注入

### 2. 日志/指标作用域匹配（P0）

**问题**：`_matches_any_scope` 子串匹配，`"192.168.1.1" in "192.168.1.10"` 为真。

**修复**：IP 走数字/点号边界正则；主机名保留子串。日志查询同时把范围下推 LogsQL（`build_logs_scope_clause`）。

### 3. 无凭证新建主机状态（P1）

**问题**：未填密码/凭证就保存 → 仍去 `test_ssh` → 标 `critical`「SSH 连接失败」。

**修复**：无凭证直接标 `pending`「未录入或关联有效鉴权凭证」；前端对应提示「待绑定 SSH 凭证」。

### 4. 提供商字段（用户反馈）

**判断**：改成**明确非必选 + 下拉分组**（两者都做）。

- 下拉改为「自建 / 本地」「云厂商」两组，文案区分「本机（OpsPilot 主机）/ 物理机 / Proxmox 虚拟机 / VMware 虚拟机」
- 标注「可选；留空默认物理机」；TS 类型 `provider?: string`
- 表格「来源」列标签与下拉对齐（本机/物理机/Proxmox/VMware，不再都显示「本地机房」）

### 5. 状态灯「未接入」点击（P1）

**问题**：灯为灰时 tooltip 写「点击配置」，实际打开空的指标/日志抽屉。

**修复**：灰灯点击跳转 `/monitoring/collectors`（安装 Alloy 入口）。
