## 一、Bug 1：总览「工作负载」象限显示 `[object Object]`

### 现象

集群详情页总览象限：

```
工作负载 [object Object][object Object][object Object]
Degraded 0 · D[object Object] S[object Object] DS[object Object]
```

### 根因

后端 `GET /clusters/{cid}/health-summary` 的 `workload_stats` 按 **Kind 分组返回对象**，不是数字：

```python
workload_stats = {
    "total": 12, "degraded": 1,
    "deployments":   {"total": 5, "degraded": 0},
    "statefulsets":  {"total": 4, "degraded": 1},
    "daemonsets":    {"total": 3, "degraded": 0},
}
```

而 `types/api.ts` 里把每个 Kind 声明成了 `number`，前端直接把它拼进字符串 / 参与运算，
于是对象被 `String()` 成 `[object Object]`。

### 修复

- `types/api.ts`：`workload_stats` 改成嵌套结构（并保留 `[k: string]: unknown` 兼容后端新增 Kind）。
- `detail.tsx` 总览象限：按 Kind 解出 `{total, degraded}`，渲染为「未就绪 X · D 就绪/总数 · S … · DS …」，
  并加 `subTip` 悬浮图例说明分数含义；`danger` 仍按总未就绪数判断。

```ts
const depStats = wlStats?.deployments ?? { total: 0, degraded: 0 }
const stsStats = wlStats?.statefulsets ?? { total: 0, degraded: 0 }
const dsStats = wlStats?.daemonsets ?? { total: 0, degraded: 0 }
```

## 二、Bug 2：可视化编辑打开 `Deployment/airspace-api` 报「资源不存在」

### 根因

两处打开编辑抽屉的入口漏传 `clusterId`：

- 工作负载 Tab 的工作负载名链接（`detail.tsx:651`）
- 资源浏览 Tab 的资源名链接（`detail.tsx:1214`）

导致 `EditTarget.clusterId` 为 `undefined`，`ResourceEditDrawer` 请求
`/clusters/undefined/resources/{ns}/{kind}/{name}/edit` → 后端 404 → 前端按空 payload 显示 Empty「资源不存在」。

### 修复

两处 `setEditTarget` 补齐 `clusterId`，并把 state 类型收紧为 `EditTarget | null`（编译期就能拦住漏字段）：

```ts
setEditTarget({ clusterId, namespace: record.namespace, kind: record.kind, name: v })
setEditTarget({ clusterId, namespace: record.namespace || '', kind, name: v })
```

## 三、连带修复（都是真实运行时故障，非代码风格）

用 `tsc -b` 全量类型检查把上一轮遗留的 **86 处错误**一次清零；其中若干是会在打开页面时直接崩的类型错误：

| 文件 | 问题 | 后果 |
|---|---|---|
| `pages/assets/databases/index.tsx` | 缺 `Row/Col` import、缺 `browserInstance`/`queryDatabase` 两个 state、重复声明 `hasPerm`、`wrap="gap"` 非法值 | **整个数据库管理页白屏崩溃**（引用未定义变量） |
| `components/db/DbObjectBrowser.tsx` | 缺 `Space` import | 对象浏览器崩溃 |
| `components/k8s/ResourceEditDrawer.tsx` | 缺 `Flex` import | 可视化编辑抽屉崩溃（即 Bug 2 的载体） |
| `pages/wireguard/index.tsx` | 缺 `Tabs` import | 虚拟组网页崩溃 |
| `api/index.ts` | 缺 `aiPlatformApi.updateSkills`（后端已有 `PUT /ai/skills`） | 技能管理保存失败 |

其余为 React 19 全局 `JSX` 命名空间移除（改用 `ReactNode`）、antd 5 非法 props
（`wrap="gap"` → `wrap gap="small"`、`Progress strokeStyle` → `strokeColor`、`Alert` 无 `title`）、
隐式 any、死查询/死变量（`NamespaceLabelsEditor` 的 `nsList`、监控看板 `isConfigured`）等。

### 其他改进

- `ClusterHealthModal`：后端返回的是嵌套 `{api:{latency}, nodes:{ready,total}, workload_stats:{…}}`，
  原前端按旧扁平结构读导致字段全为空。重写为读嵌套结构，未就绪工作负载展示「就绪/总数」。
- `NamespaceLabelsEditor`：原 `nsList` 查询是死代码且拿不到 labels；改为复用 edit-form 只读通道回填 labels。
- `DbTicket` 类型补齐 `database` / `execute_after` / `has_backup` / `has_rollback`（工单详情抽屉原本用 `as any` 读）。
