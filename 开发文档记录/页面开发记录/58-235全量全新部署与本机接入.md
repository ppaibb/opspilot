## 三、抓到的问题（均已记录并修复）

### ① daemon.json 引号被 shell 转义写坏 → dockerd 起不来（工具链问题）

SSH 内联 heredoc 写 JSON 时 `\"` 被吞成 `\`，daemon.json 内容损坏，
dockerd 启动即 `invalid character '\'`；且 systemd 失败计数打满后
`Start request repeated too quickly` 不再自启，需 `systemctl reset-failed docker`。
**改法**：远端写文件一律 base64 传递或本地脚本 `ssh ... 'tr -d "\r" | bash -s'` 管道，
不再内联复杂引号。

### ② 仓库 shell 脚本是 CRLF，Linux 上执行即炸（仓库级，已修）

`bash install.sh` 第一行就报 `set: pipefail: invalid option name`——
工作树里 `install.sh` 是 CRLF（309 行全带 `\r`），仓库也没有 `.gitattributes`。
这与 `启动-*.bat` 在 Windows 下共存的工作流直接冲突。
**修复**：

- 新增根 `.gitattributes`：`*.sh`、`*.alloy` 强制 `eol=lf`
- `deploy/offline/install.sh` 工作树转 LF；目标机 `sed -i 's/\r$//'` 同步修复

### ③ 本机资产名 = 容器 ID（代码级，已修）

后端自注册 `ensure_localhost_asset()` 用 `socket.gethostname()` 当主机名——容器里
拿到的是容器 ID，资产列表显示 `87df9af3ec0d (本机)`。真实主机名 `HOST_NAME`
只注入了 Alloy（监控 compose），后端容器没有。
**修复**：

- `backend/app/db/bootstrap.py`：`hostname = os.environ.get("HOST_NAME") or socket.gethostname()`
- `deploy/offline/install.sh` `write_backend_env()`：app/.env 增加
  `HOST_NAME=${HOST_NAME:-$(hostname)}`
- 235 上重建后端镜像并重启；存量资产用 SQL 改名为 `testserver-305 (本机)`
  （bootstrap 幂等不覆盖已有资产）

### ④ 主机监控图表抽屉无数据、日志却有（代码级，已修；上个环境同样存在）

**现象**：主机管理点「监控图表」抽屉显示「该主机暂无指标」，同一台主机的
「相关日志」却有数据。

**根因**（235 实测二分定位）：

1. 抽屉调 `/monitoring/host-metrics`，后端把 **IP + 资产名** 拼进
   `instance=~"(...)"` 正则；只传 IP 时也会自动从资产表补名字。
2. `prom_instance_regex` 用 `re.escape` 转义，产出 `\-`（连字符）、`\ `、`\(本机\)`
   这类**反斜杠转义**——VictoriaMetrics 把它们当非法 WITH 表达式直接 **422**
   （逐个二分验证：`[.]`/裸 `-`/裸空格/`[(]` 全 200，只要含 `\-` 必 422）。
3. `host-metrics` 对查询异常静默降级为空序列 → 抽屉全空。
4. 资产名 `testserver-305 (本机)` 必含 `-`，**所有带连字符名字的主机全中**；
   日志链路走 LogsQL 不经过该正则，所以日志一直正常——这就是「图表没数据、日志有数据」。

代码里其实早有预警（docstring 写着「VM 对反斜杠转义返回 422」），但只修了点号，
`re.escape` 本体还在产出其余转义。

**修复**：

- `dashboard.py` `prom_instance_regex`：废弃 `re.escape`，特殊字符改写**字符类**
  （`[.]`/`[(]`/`[)]`/`[+]`…），连字符/空格/CJK 直接字面量，**全程零反斜杠**；
  pattern 同时保持 Python `re.fullmatch` 与 VM 正则双兼容
- 契约测试 +2 例：连字符/括号名断言 `"\" not in pattern` + fullmatch 语义不回归
- 235 重建后端镜像复验：`host-metrics` 返回 61 点，`cpu=1.9 / memory=4.25 /
  load1=0.22` 真实数据

## 四点五、监控图表抽屉 UI 打磨（用户反馈「局促不好看」）

修复④出数据后，用户反馈抽屉里图表局促。重排三处并部署 235 + Playwright 截图实证：

1. **加宽 + 双列**：Drawer 560 → 760；CPU / 内存并排（`ChartCard` 网格卡），
   网络流量通栏；三段纵排变两行，滚动大幅减少
2. **坐标轴去旋转**：`MetricChart` x 轴标签 `rotate: 20` → `0 + hideOverlap`，
   原来 45° 斜排长日期标签是最挤的来源；顺带把 grid.top 从按 subtitle 改为按
   legend 判断（单序列图多 24px 纵向空间）
3. **口径行收敛**：PromQL 长公式单行省略号 + 原生 title 悬浮看全；字号 11
4. **默认时间窗 24h → 1h**，时间窗补 1 小时档（5 分钟 / 1 小时 / 24 小时 / 7 天），
   新主机打开即见满屏曲线而非右侧一个尖
5. 修 grid blowout：图卡 `minWidth: 0 + overflow: hidden`，否则 `1fr` 列被
   nowrap 口径文本撑出视口（首轮截图内存卡右侧被裁，第二轮修复）
6. **补磁盘使用率通栏**（第二轮反馈「还剩空间加磁盘」）：消费后端已有的
   `disk_partitions` + `disk_<盘>` 字段，CPU/内存并排 → 磁盘通栏 → 网络通栏三行填满
7. **日志抽屉撑满**（同轮反馈「没占满」）：原 `scroll.y` 写死 360 导致分页下方大片
   留白 → 卡片 flex:1 + ResizeObserver 实测卡片高度回推 `scroll.y`（分页贴底），
   宽度 680 → 760 与指标抽屉对齐
8. **日志抽屉假翻页修复**（第三轮反馈「点翻页是增加条数」）：后端行 `id` 实为
   **流 ID**（同容器日志共用，实测 100 行只有 4 个唯一 id），抽屉 `rowKey="id"`
   大面积重复 key → React reconciliation 失效，翻页时旧行删不掉、新行追加。
   修法：全量数组下标 + 时间拼复合 key（与监控日志页已有规避同款）；
   Playwright 实证翻页后行数恒 20、内容整体替换
9. **日志搜索**（同轮需求）：工具行加 `Input.Search`（回车/按钮提交、可清除），
   关键词走服务端 LogsQL 全文过滤（不只筛已加载的 100 条）；摘要行显示
   「搜索「词」」，空结果给「无匹配日志」引导；X 清除同步重置过滤
10. **搜索二轮修复**（第四轮反馈「点搜索后条条没了」+ 中文搜不到）：
    - **工具条被空态顶掉**：0 结果时整个卡片（含搜索框）被 EmptyState 整体替换，
      想改词都没入口 → 结构改为「只要拿过一次数据工具条就常驻，空态/查询错误
      收进卡片内部」；再加 `placeholderData: keepPreviousData`，搜索/切窗期间
      保留上一份结果平滑过渡，表格挂 `loading`
    - **中文 0 命中**：VLogs 分词下裸词 `告警` 匹配不到子串，实测 `*告警*`
      通配才有命中 → 新增 `toLogsQL()`：逐词清洗 LogsQL 元字符（`"`/`[` 会 400）
      后包 `*词*`、空格拼接（=AND，已实测）；空输入回退 `*`
    - Playwright 实测：搜「告警」20 行全命中且搜索框在；搜不存在词 → 卡片内
      空态 + 工具条/关键词完好可改
11. **日志抽屉横向滚动 + 完整查询深链修复**（第五轮反馈）：
    - 消息看不全 → 表格加 `scroll.x=1120`（可视 ~710），消息列定宽 900；
      时间/级别 `fixed:'left'` 冻结，右滚读长行时时间戳不丢
    - 「完整查询」带 `?host=IP` 到日志查询页，原 compose 只生成 `host:IP`，
      而容器日志的 `host` 标签是主机名、IP 落在 `instance` → 查询页 0 行。
      `composeLogsQuery` 把 `host` 标签展开为 `(host:v OR instance:v)`——
      深链带 IP、标签下拉带主机名都命中（labelFilter 契约测试 +2 并同步既有断言）
    - Playwright 实证：抽屉 scrollWidth1120>clientWidth710 冻结列 42 个；
      完整查询落地查询页「实际查询 `(host:IP OR instance:IP)`」命中 200 行 + 直方图
