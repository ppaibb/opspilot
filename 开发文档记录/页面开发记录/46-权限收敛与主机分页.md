## 一、权限显隐收敛（P1/P2/P2b）

**根因**：6 条路由标注「RBAC 无此键，不设防」——`/monitoring/metrics`、`/monitoring/alerts`、
`/settings/im`、`/settings/scheduled-tasks`、`/settings/permissions`、`/tools/changes`
对所有角色可见，只读用户点进去是 403 死胡同。

**修法（补权限键而非继续不设防）**：
- `app/core/rbac.py` PERMISSION_CATALOG 新增 6 键：
  `module.monitoring.metrics` / `module.monitoring.alerts` / `module.tools.changes` /
  `module.settings.permissions` / `module.settings.scheduled` / `module.settings.im`
  （个人 IM 是自助能力，各模板**默认全员开**；其余按模板语义）
- 模板默认值：运维全开；开发补 metrics/alerts/im；域名管理员/只读补 im；
  DBA 自定义角色（system_configs 存储）已手工补 alerts/metrics/im
- 前端 `routes.ts` 6 条路由挂上权限键，菜单/搜索自动按权限收敛
- 仪表盘：活跃告警卡与告警趋势图的显隐从 `module.monitoring.live` 改为
  `canAlertCard = has('module.monitoring.rules')`（stats 接口的真实权限），
  无权限用户不再看到 403 兜底的「0 条告警」
- 权限键经由 `PERMISSION_DEFAULTS`（默认 False）自动进入所有模板与权限管理页，
  与用户确认的设计一致：**能力授予全在系统设置里灵活调整**

**验证**：viewer01 登录后仅剩 仪表盘/AI 能力/监控中心（看板+日志）/系统设置（仅个人 IM），
仪表盘无告警卡与趋势图（截图 15）；API 层 access 矩阵核对通过。

## 三、主机页迁服务端分页/筛选（第 7 项）

- 后端 `/api/assets` 补 `offline` 语义别名（前端「离线」= 非健康，与单值精确匹配不同）
- 前端：
  - `assetsApi.listPaged({limit, offset, q, status, source, group_id})` 返回页数据 + X-Total-Count
  - 主机表格改**受控分页**（current/pageSize/total 全部来自服务端），
    缓存 key 挂 `['assets','paged',...]`——任何 `['assets']` 失效（增删改）自动刷新当前页
  - search(300ms 防抖)/状态/来源/分组 四筛选下沉服务端；筛选变化自动回第 1 页
    （重置逻辑挂在包装 setter 里，规避 React Compiler 的 effect 内 setState 规则）
  - configFilter（采集状态）是纯前端态，本地叠加保留
  - CSV 导出改为导出**当前筛选的全量**（导出时按当前筛选参数拉 limit=0 全量）
  - 统计卡/采集轮询/编辑抽屉跟随仍用轻量全量缓存（不破坏既有交互）
- 验证：主机页分页「共 8 台」正常（截图 16）；API 层 `q=zzz → X-Total-Count: 0`

## 四、删除用户能力（第 8 项）

- 后端 `DELETE /api/settings/users/{id}`（`app/api/settings.py`）：
  - 高危票据 `require_risk_ack("action.settings.users.manage", "delete")`，
    动作已注册 `ACTION_RISK_LEVELS` 为 **high**
  - 保护：不能删自己；不能删最后一个可用管理员
  - 审计留痕（action=删除用户，risk_level=high）
- 前端用户页操作列加危险删除按钮（`confirm('users:delete', ...)` 二次确认 +
  `fetchRiskTicket` 显式票据，遵循多请求场景约定）
- e2e 4 例：无票据 403 / 带票据删除成功且票据一次性 / 删自己 400 / 末位管理员保护
- **顺手清理**：27 个 e2e 残留用户（e2e_noemail_* + e2e_del_*）全部经票据链删除，
  系统现只剩 admin/ops01/dba01/viewer01 四个正式账号
