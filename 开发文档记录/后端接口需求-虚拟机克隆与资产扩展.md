# 后端接口需求规格说明书 — 虚拟机克隆 (VM Clone) 扩展

> **创建时间**：2026-08-04  
> **面向对象**：后端开发团队  
> **项目名称**：OpsPilot 运维平台

---

## 一、 需求背景

为了让 OpsPilot 的虚拟机资产管理能力更加直观、方便，前端页面在 `/assets/vms` 规划了独立的 **“虚拟机克隆”** 交互。现需后端新增独立的克隆 API `POST /api/vms/{id}/clone`，在虚拟化平台（Proxmox / VMware / 云厂商）中直接触发异步克隆。

---

## 二、 拟新增接口规格

### 1. 虚拟机克隆接口 (POST `/api/vms/{id}/clone`)

* **接口路径**：`POST /api/vms/{id}/clone`
* **功能描述**：根据指定的源虚拟机 ID (`id`)，直接创建并派生一台新虚拟机。
* **请求头**：`Authorization: Bearer <access_token>`
* **Path 参数**：
  * `id`: `string` — 源虚拟机 ID (例如 `pve-100`)

* **Request Body (JSON)**：
```json
{
  "name": "vm-web-01-copy",          // [必填] 新虚拟机名称
  "full_clone": true,                // [可选] 是否完整独立克隆（true 为 Full Clone，false 为 Linked Clone，默认 true）
  "target_node": "pve-node-02",      // [可选] 目标宿主节点（留空默认继承源节点）
  "target_storage": "local-lvm",     // [可选] 目标存储池（留空默认继承源存储）
  "start_after_clone": false         // [可选] 克隆完成后是否自动开机（默认 false）
}
```

* **Response Success (HTTP 200 / 201)**：
```json
{
  "id": "pve-101",
  "name": "vm-web-01-copy",
  "provider": "proxmox",
  "node": "pve-node-02",
  "status": "stopped",
  "ip": "192.168.1.101",
  "os": "Ubuntu 22.04",
  "cpu_cores": 4,
  "memory_gb": 8,
  "system_disk_gb": 50,
  "description": "克隆自 vm-web-01"
}
```

* **Response Error (HTTP 400 / 404 / 500)**：
```json
{
  "detail": "源虚拟机不存在或底座平台不支持克隆"
}
```

---

## 三、 规范约定

1. **统一返回**：成功后直接返回新虚拟机的对象 JSON。
2. **审计日志**：克隆属于高危变更，后端需自动写入审计日志 (`settings/audits`)。
