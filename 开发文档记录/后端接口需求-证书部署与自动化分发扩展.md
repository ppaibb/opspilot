# 后端接口需求规格说明书 — 证书部署与自动化分发扩展

> **创建时间**：2026-08-04  
> **面向对象**：后端开发团队  
> **项目名称**：OpsPilot 运维平台

---

## 一、 需求背景

在 SSL 证书管理中，除了已有的“主机 SSH 分发”，前端新增了**云厂商（阿里云/腾讯云/AWS/Cloudflare）CDN 与 ALB 负载均衡的证书自动分发推送**需求。

现需要扩充 `POST /api/certificates/{id}/deploy` 接口的规格，使其同时支持**主机 Nginx 热重载**与**云平台一键更新**两大部署场景。

---

## 二、 扩充后的接口规格

### 1. 证书部署推送接口 (POST `/api/certificates/{id}/deploy`)

* **接口路径**：`POST /api/certificates/{id}/deploy`
* **功能描述**：触发证书公私钥向多台目标主机（SSH/SFTP + Reload）或云平台（CDN / 负载均衡）推送替换。
* **请求头**：`Authorization: Bearer <access_token>`
* **Path 参数**：
  * `id`: `string` — 证书 ID (例如 `cert-101`)

* **Request Body (JSON)**：
```json
{
  "target_type": "host",                       // [必填] 部署目标类型: "host" (主机/Nginx) 或 "cloud" (云厂商)
  
  // ── 当 target_type 为 "host" 时必填 ──
  "asset_ids": ["host-1", "host-2"],           // 目标主机 ID 数组
  "cert_path": "/etc/nginx/ssl/server.crt",    // 证书存储绝对路径
  "key_path": "/etc/nginx/ssl/server.key",      // 私钥存储绝对路径
  "reload_cmd": "systemctl reload nginx",      // 部署完成后执行的热重载命令

  // ── 当 target_type 为 "cloud" 时必填 ──
  "cloud_provider": "aliyun",                  // 云厂商: "aliyun" | "tencent" | "aws" | "cloudflare"
  "cloud_account_id": "acc-8890"               // 云服务商 API 密钥账号 ID
}
```

* **Response Success (HTTP 200 / 201)**：
```json
{
  "cert_id": "cert-101",
  "deploy_status": "success",
  "message": "已成功分发推送证书",
  "results": [
    { "target": "host-1", "status": "success", "message": "SSH 证书替换与 Nginx reload 成功" },
    { "target": "aliyun-cdn", "status": "success", "message": "云厂商 API 域名证书更新成功" }
  ]
}
```

* **Response Error (HTTP 400 / 500)**：
```json
{
  "detail": "部署失败：目标主机 SSH 连接失败或云账号 API Key 权限不足"
}
```

---

## 三、 规范约定

1. **多目标分发**：支持主机模式与云厂商 API 模式的灵活调度。
2. **审计日志**：分发部署属于敏感操作，需记录在系统审计日志中。
