# OpsPilot 部署说明

## 形态

| 形态 | 适用 | 入口 |
|---|---|---|
| 本机开发 | 日常开发调试 | `启动-全部.bat`（前端 5173 + 后端 8001） |
| Docker Compose | 单机交付 / 演示 | `docker compose up --build` → 前端 `http://localhost:8080` |
| 生产分步 | 已有 PG / 反代 | 见下文「生产分步」 |

## 一、本机开发

前置：Node 22+ / pnpm 10 / Python 3.12 / PostgreSQL。

```bat
copy backend\.env.example backend\.env
rem 编辑 backend\.env：SECRET_KEY、CREDENTIAL_ENCRYPTION_KEY、DATABASE_URL、INIT_ADMIN_*

启动-全部.bat
```

统一验证（提交前必跑）：

```bat
检查-全量.bat
检查-全量.bat --secret-scan
```

## 二、Docker Compose

```bat
copy backend\.env.example backend\.env
rem 至少改 SECRET_KEY / CREDENTIAL_ENCRYPTION_KEY / INIT_ADMIN_PASSWORD
set POSTGRES_PASSWORD=强口令
docker compose up --build -d
```

- 前端：`http://localhost:8080`（nginx，`/api` 反代到 backend:8001）
- 后端直连：`http://localhost:8001/docs`
- 数据卷：`pgdata`（库）、`backend-storage`（上传/生成物）

首次启动 lifespan 会 `create_all` + `ensure_model_columns`。生产建议：

```yaml
# docker-compose.override.yml
services:
  backend:
    environment:
      DB_AUTO_CREATE_TABLES: '0'
```

然后执行迁移：

```bat
docker compose run --rm backend alembic upgrade head
```

## 三、生产分步

1. **数据库**：独立 PostgreSQL 16，建库 `opspilot`，账号最小权限。
2. **后端**：
   ```bat
   cd backend
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   set DB_AUTO_CREATE_TABLES=0
   .venv\Scripts\python.exe -m alembic upgrade head
   .venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8001
   ```
   建议用 NSSM / systemd 托管，前置 Nginx/Caddy 做 TLS。
3. **前端**：
   ```bat
   cd frontend
   pnpm install --frozen-lockfile
   pnpm run build
   ```
   将 `frontend/dist` 交给任意静态服务器，反代 `/api` → 后端 8001（需支持 WebSocket 与 SSE，参考 `frontend/nginx.conf`）。

## 四、环境变量（backend/.env）

| 变量 | 说明 |
|---|---|
| `SECRET_KEY` | JWT 签名密钥，必须强随机 |
| `CREDENTIAL_ENCRYPTION_KEY` | 凭证加密密钥，**更换会导致已存凭证无法解密** |
| `DATABASE_URL` | `postgresql+psycopg://user:pass@host:5432/opspilot` |
| `INIT_ADMIN_*` | 首次启动种子管理员 |
| `DB_AUTO_CREATE_TABLES` | `1` 开发自动建表/补列；`0` 生产只信 Alembic |
| `TERMINAL_SFTP_UPLOAD_MAX_MB` | SFTP 上传上限 |

## 五、监控分体部署（推荐客户环境）

监控套件（VictoriaMetrics / VictoriaLogs / Grafana）可以与 OpsPilot 后端**分机部署**。

**首次启动**由 bootstrap 写入连接配置（已配置则不覆盖）：

| 环境变量 | 含义 | 示例 |
|---|---|---|
| `MONITORING_HOST` | 监控套件主机（生成 :8428/:9428/:3000） | `192.168.3.99` |
| `VM_URL` / `VLOGS_URL` / `GRAFANA_URL` | 精确覆盖（优先） | `http://192.168.3.99:8428` |

未设置时默认 `127.0.0.1` 标准端口。之后改地址：**系统设置 → 系统管理 → 监控连接**（直接落库）。

```text
[监控机 192.168.3.99]          [OpsPilot 后端]         [业务主机]
  VM      :8428  ◄── 查询 ──── 后端 vm_url
  VLogs   :9428  ◄── 查询 ──── 后端 vlogs_url
  Grafana :3000  ◄── 浏览器 ── grafana_url
  ▲ remote_write / 日志写入 ◄── Alloy Agent
```

在 **系统设置 → 系统管理 → 监控连接** 填三段地址：

| 字段 | 指向 | 示例（分体） |
|---|---|---|
| VictoriaMetrics / VictoriaLogs | 后端 → 存储 | `http://192.168.3.99:8428` / `:9428` |
| 采集写入（可空） | Agent → 存储 | 留空自动推导 `/api/v1/write`、`/insert/elasticsearch` |
| Grafana / VMUI | 浏览器 → UI | `http://192.168.3.99:3000` |

一体化 Docker（同一 compose 网络）才使用容器名 `http://opspilot-victoriametrics:8428`。
**不要**把 `127.0.0.1` 填给需要跨机访问的地址。

监控栈自身：

```bash
docker compose -f deploy/monitoring/docker-compose.yml up -d
# retention：指标 30d / 日志 7d，数据卷独立
```

## 六、运行日志与审计

| 类型 | 落点 | 说明 |
|---|---|---|
| 应用运行日志 | `backend/logs/app.log` | 启动时由 `app.core.logging.setup_logging()` 配置；**10MB × 5 份滚动**（`app.log.1`…）；可用 `LOG_DIR` 改目录 |
| uvicorn / SQLAlchemy | 同上 | 关键 warning+ 落同一文件 |
| 业务审计 | 数据库 `audit` 表 | 登录、高危操作、工单等**以 DB 为准**，不在文本日志 |

运维建议：
- 把 `logs/` 挂到独立卷/磁盘，或用采集车/系统 syslog 外送
- 生产可把 `logs/` 交给 logrotate / Docker 日志驱动，二选一即可
- 文本日志默认 **INFO**；排障可临时把 root 调 DEBUG（改 `setup_logging(level=...)`）

## 六、健康检查

- 后端：`GET /api/settings/login-page`（免鉴权）
- 业务连通：登录后 `GET /api/auth/me`

## 七、升级注意

- `requirements.txt` 已钉死版本；升级依赖先改文件再全量 `检查-全量.bat`。
- 模型加列：开发库靠 `ensure_model_columns` 兜底；生产必须出 Alembic 迁移。
- kubeconfig、`.env`、`*.log` 不要打进镜像（Dockerfile 已只 COPY 代码目录）。
